# 实施路线图

需求基线见 `../product/requirements.md`，架构见 `../architecture/overview.md`，实际进度以 `status.md` 为准。T01–T12 为稳定任务编号；任务内部可拆子步骤，但只有满足全部验收条件才算完成。

## 阶段 1：可用的手动记账闭环

| 任务 | 范围与依赖 | 完成验收 |
| --- | --- | --- |
| T01 工程基础 | 仓库规范、开发环境、后端与网页骨架、登录、配置、数据库迁移、日志、CI | 文档能够指导从干净环境启动；登录及基础运行流程可验证；迁移与自动检查通过 |
| T02 账务核心 | 依赖 T01；独立账本、分类、多币种账户、精确金额、分录、余额、转账、修改历史 | 期初余额和收支正确；转账不新增收入费用；精度、隔离与修改场景测试通过 |
| T03 API 与数据契约 | 与 T02 协同；版本化接口、稳定 ID、版本、重复请求保护、删除标记 | 契约与实现一致；重复请求不重复入账；为后续同步保留明确扩展点 |
| T04 基础网页 | 依赖 T02/T03 可用接口；中英文、地区资料模板、账户分类、手动记账、流水、手机适配 | 从创建个人与公司账本到录入、查询、修改、查看余额的完整流程可操作 |

阶段验收：真实接口和持久化数据驱动完整手动记账闭环；网页需联网。基础备份从本阶段建立，但完整恢复与运维完善属于 T10。

### T02 的实施增量

以下是同一个 T02 内的开发顺序，不替代任务的整体放行条件。每个增量单独 PR，T03 的契约随实际服务共同实现。

| 顺序 | 交付 | 对应检查与边界 |
| --- | --- | --- |
| T02-1 | 不可变资产身份、精确数量、数值数据库边界 | A-07 底层精度；无账户余额或业务 API。见 ADR 0003。 |
| T02-2 | 主体、账本、账户、账户支持资产、分类模板复制及真实迁移 | 验证 A-01/A-02/A-03 的结构部分；同名对象独立，跨账本引用拒绝。资产目录约束禁止修改已引用精度。 |
| T02-3 | 原子分录、期初余额、手工收支、分类拆分、按账户/资产计算余额 | 验证 A-03 的 USD 75/EUR 90；期初不算收入，非法/不平衡过账整体回滚。前置业务操作 ID、审计字段和重复请求保护。 |
| T02-4 | 同币种转账、信用卡消费与还款 | A-04/A-06；本金不算费用，并发重复请求只入账一次，一侧失败则全部回滚。跨主体代付属于 T07。 |
| T02-5 | 换汇、实际转出/转入和手续费 | A-05/A-07；USD 898/EUR 90、BTC 0.89999，不用行情替代成交量。 |
| T02-6 | 更正、撤销、版本冲突与审计 | 支出 100 改为 120 后费用为 120；撤销恢复余额并保留历史。使用中的账户/分类归档不破坏引用。相关异常用例随实现补充。 |

完整 A-01 地区界面/证件、A-08 网页业务操作及 A-09 财务附件恢复仍需跨任务联调。只完成上表某个底层检查，不能把这些完整案例标为通过。

## 阶段 2：票据与经营业务

| 任务 | 范围与依赖 | 完成验收 |
| --- | --- | --- |
| T05 本地票据处理 | 依赖阶段 1 契约；PDF/照片、文字提取与本地 OCR、队列、原件对照、拆分类别、重复提示 | 中英文样本完成上传到人工确认；识别异常可重试；未经确认不入账 |
| T06 经营单据 | 依赖 T02/T03；客户供应商、项目、应收应付、部分结算、商业 Invoice、周期草稿 | 分次付款和合并结算正确；周期任务重试不重复生成；可导出中英文 Invoice PDF |
| T07 代付与报销 | 依赖 T06；个人/公司代付、往来、报销偿还、付款关联、可选开启 | 代付到结清关系可追溯；偿还不重复产生费用；再次导入付款可关联原业务 |

阶段验收：票据、业务单据和资金流水连接完整；可验证一笔账单分次结清、重复流水关联以及代付报销闭环。

## 阶段 3：完整网页版本

| 任务 | 范围与依赖 | 完成验收 |
| --- | --- | --- |
| T08 汇总与估值 | 依赖 T02/T06/T07；主体筛选、分类映射、现金/经营视角、内部交易、法币与加密资产报价 | 汇总可追溯明细；内部往来不重复；原币保留；历史/最新价格、缺失价格及手动修正可验证 |
| T09 提醒系统 | 依赖公司及业务资料；地区/税务规则、条件、日期计算、手动覆盖、站内和邮件提醒 | 适用规则有来源和核验日期；缺资料可识别；日期案例、重复发送保护和完成回执可验证 |
| T10 部署与运维完善 | 持续积累，阶段末整体验收；导出、备份恢复、监控、升级回滚、自有服务器部署 | 干净环境恢复数据库和附件并核对金额关联；部署、迁移及回滚步骤有实际证据 |

阶段验收：已确认网页范围全部可用；报表金额正确、提醒依据可追溯、备份可恢复。具体税务规则实施时逐项核实官方资料，不能仅由国家或成立日期猜测。

## 阶段 4：Android / iOS 与离线同步

| 任务 | 范围与依赖 | 完成验收 |
| --- | --- | --- |
| T11 同步服务 | 依赖 T03 及稳定业务模型；设备、增量同步、版本冲突、删除同步、附件重试 | 重复请求不重复记账；并发修改保留冲突；删除不被旧设备复活；中断可恢复 |

## 并行与集成

T02/T03 的数据与接口由集成负责人协调。契约稳定后，网页、票据与经营模块按边界并行；报表建立在验证过的账务数据之上。每个 PR 更新状态、证据和下一步，重要取舍补充 ADR。
