# OCR 同机验收协议

本协议落实 [ADR 0019](../architecture/decisions/0019-local-ocr-worker.md)，字段计分实现为 [scoring.py](../../scripts/ocr_benchmark/scoring.py)。进度只见 [status.md](status.md)，实际制品摘要、环境、命令和结果留在对应 PR 与实测报告；本文不代表已运行引擎或已经达标。

旧正式集已转为诊断证据，见[只读字段归因](ocr-formal-diagnosis.md)；后续新种子验收遵循当前用户指示，不能复用旧正式集作验收。

本轮现行决定见 [ADR 0020](../architecture/decisions/0020-ocr-prefill-and-review.md)：旧正式集不可再验收，改进只用DEV；新种子清晰文字层/OCR冻结后仅运行一次，热三轮/冷三次、两引擎同资源。95%门槛只决定OCR建议值预填；均不达标时Tesseract全部OCR字段待确认，文字层仍按原规则。以下v1五轮/辅助组及硬停止运行器保留作历史协议；普通CI不运行旧正式集。新清晰模式的输入、安全、资源与完整性失败不能作为质量降级掩盖。

新清晰集使用采样种子 `2026100501`：改变独立虚构真值的日期，金额按整数倍改变，保持恒等式、符号、前导零/千分位/负零、重复交易、12模板与三载体覆盖；真值及配置先写出再交给原渲染器。渲染器的历史固定seed `20261004`不参与清晰样本采样，保留以免改写v1生成器及冻结证据；报告分别记录sampling_seed与render_seed。新集只生成清晰36份和4份DEV，退化/错误组为空。`formal_freeze prepare-clear --source-dir … --corpus-dir …`生成后，仅对DEV运行候选；`freeze-clear --corpus-dir … --assets-dir … --selection … --output …`创建不可覆写的快照。源码/锁/模型/完整制品/独立答案/页行映射/当前DEV证据均在任何正式识别前验证，后续验证只能比较，不能刷新摘要。

## 语料与冻结顺序

本轮清晰运行入口为 `formal_run --clear-frozen …`：完整矩阵12文字/24 OCR，无辅助组，冷三次、热三轮AB/BA/AB。两候选继续统一2 CPU/4 GiB（用户允许冻结前调整至4/8，本轮保留已验证资源）；参数、模型和资源在冻结后不再修改。OCR工作流仅在main手动勾选 `clear_acceptance` 时运行，先发布新输入与不可覆写清单制品，再识别；PR检查不做正式识别。复用同次运行的独立DEV结果，DEV制品与新清单的摘要逐项核对。双引擎质量均未达标时报告临时Tesseract全字段确认；实验缺失、文字层失败或不稳定仍判运行失败，不将原预测改成review来影响评分。

[truth.json](../../tests/fixtures/ocr/truth.json) 是先于生成器与识别器逐项写定的独立真值：简中、繁中、英文、混排各三个模板，共八张发票/贷项/收据、四份流水。它保存字面正文、原始金额及规范字段，包含五种法币、负数、税额、千位分隔、重复同额交易和跨页、多币种流水。每份文档首页标明“虚构测试票据 / FICTIONAL TEST DOCUMENT”，续页有打印页码及虚构条目；组织、条目均虚构，不使用真实账单、账号或证件。

真值由开发助手手工写定，并由另一助手逐项审阅、用独立整数运算核对；不声称真人标注或由用户复核，不从 OCR 输出反推答案。后续生成器仅按真值排版，不计算识别答案；解析器不得读取真值。

| 分组 | 固定构成 | 用途 |
| --- | --- | --- |
| 清晰文字层 | 12 模板各一份文字 PDF | 金额、日期、币种关键字段精确率 100% |
| 清晰 OCR | 同 12 模板各一份扫描 PDF、一份照片，共 24 份 | 两候选分别达到关键字段精确率 ≥95% |
| 退化 | 旋转、低对比、模糊、透视各三份，共 12 份 | 报告错误发现和人工路径，不计为清晰样本达标 |
| 错误输入 | 损坏、加密、超页数、超像素、超流大小、缺模型、超时、已有乱码文字层八类 | 逐类验证有界失败；已有层不得改走 OCR |

清晰日期统一明确 ISO，不宣称清晰集包含歧义日期。退化组固定另含歧义日期 `01/02/2026`、只有 `$` 的币种、冲突重复合计各一例，预期必须标为需确认；其余字段仍逐项评价，不能将整张票据删除。已有乱码层另在错误组验证文字层优先。

排版固定 A5 420×595 pt、300 DPI，pypdfium2 5.13 实际为 1751×2480 像素；两个跨页模板保持两页 PDF。照片将这两页按顺序竖向拼接成一个 1751×4960 图像，不裁掉任一行，约 8.7M 像素；图片不从 metadata 猜 DPI。扫描 PDF 嵌入冻结 JPEG/DCT 字节，不能为容纳测试生成器的未压缩图像而抬高生产流预算。

先冻结真值和本协议，再完成独立的共享解析器、生成器及开发样本。开发样本与正式样本分离，不纳入上述 36 份；只在开发样本上选定一个 Tesseract 配置（包括 fast/best、语言、PSM）。在正式运行前提交全部正式输入/字体/模型/依赖/配置的实际 SHA-256 清单，固定随机种子 20261004，并证明同一 Linux 环境两次生成字节一致。未取得的制品不填假摘要。

开发配置选择固定为 `fast/best × PSM 6/3/11` 六组，全部使用显式 `eng+chi_sim+chi_tra`，不按票据切换语言。每组及单一 Paddle small 配置分别对 D01–D04 四份开发扫描 PDF 在同一持久进程内识别两次；排除时间记录后，完整文字、框、字段及状态须逐项一致。只计首轮字段结果，先取聚合 `C/(T+E)` 最高者，再取 CER 最低者，仍相同依次优先 fast、PSM 6→3→11。该规则在运行开发样本前写定，不能拿第二次较好的预测覆盖第一次。开发结果不代替正式门槛。

## 载体生成与复核

构建参数来自 [corpus-config.json](../../tests/fixtures/ocr/corpus-config.json)，开发样本来自独立的 [development.json](../../tests/fixtures/ocr/development.json)。开发样本使用另外的虚构日期/金额，全部排除正式分母。生成器只用字面正文和原始行单元格排版；评分答案仅复制先写定的真值并按已知载体编号，不读取识别输出补答案。

```sh
python -m scripts.ocr_benchmark.corpus generate --source-dir build/corpus-sources --output-dir build/fictional-corpus
python -m scripts.ocr_benchmark.corpus verify --output-dir build/fictional-corpus
```

输出目录必须是新目录，字体来源须先经摘要验证，生成不联网。字号、字宽、完整边界和页码逐项检查，超界失败，不缩字或裁剪。固定 ReportLab 的环境时间、PDF 标识、JPEG 参数及全部扰动参数；在同一 Linux 环境的独立进程、不同目录验证所有输出字节相同。清晰文字 PDF 经现有准备流程与共享解析器检验，计分仍使用独立真值。

Linux 实际制品由 [corpus-frozen.json](../../tests/fixtures/ocr/corpus-frozen.json) 锚定完整 manifest 摘要与全部资产摘要，CI 必须重建并逐字节摘要比对。字体、字面真值、配置、开发样本、生成代码和构建锁一并绑定；Windows 检查不冒充 Linux 制品。后续正式引擎验收先验证这个外部冻结清单，不能只接受可随输入重写的自包含 manifest。

扫描 PDF 只有 JPEG/DCT 图像，不含隐藏文字；照片保留完整跨页正文。JPEG 有损，因此不同载体的像素可以不同：每个载体分别核对真实准备后的尺寸与像素，两引擎随后消费该载体相同的准备结果。不能把源文字 PDF 的像素摘要冒充扫描 PDF 或照片的摘要。

初版约数 1750 宽与 SDK 的浮点乘法顺序不一致；预算预检使用与 PDFium 相同的 `scale=dpi/72` 后 `ceil(width*scale)`。新增的一列计入既有像素/字节上限，并在原生分配前拒绝超预算；不改 DPI、纸张、真值或门槛。表格最后分隔符与说明文字保留真实间距，避免提取器把两者粘成跨列词框。

八类错误是八个验收案例：六类生成实际错误文件；“缺模型”和“超时”引用合法扫描件及固定运行情景，必须在后续引擎步骤实际验证。文件生成、清单存在或测试描述不能代替这两项运行验收。实际 manifest 保存相对文件名、字节数、SHA-256、来源编号、正文、答案及扰动；全部评分映射只能进入验收工具，不能进入共享解析器或生产识别输入。

## 共享字段解析与身份

worker 和 benchmark 使用同一解析器；输入只有实际文字、词框和页面几何，不能输入文件名、模板编号、样本编号、真值、预期字段列表或排版映射。保留候选文字、原始字段与证据。日期只接受无歧义 ISO，币种须显式代码；未知符号不猜。金额去合法千位分隔与显式正号、规范前导零及负零，规范值至少两位小数，仅删除第二位之后的末尾零；额外非零小数精度保留精确值并标需确认，不舍入。使用整数系数/尺度，不经 float 或默认 Decimal 上下文；不作 O→0 等模糊纠错。原始拼写始终留在证据中，确认财务命令另冻结用户最终选择的原始 JSON。

适配器按真实垂直重合且横向不重叠的框拼出可读行文本；歧义时保留逐框顺序。只改变转录行序与空白，不修改任何Word文字/坐标，不插入分隔符或按值分组。字段解析继续读取原框并保留跨列、重叠拒绝；可读文本不能作为确定字段的补救路径。

计分前输出 `{path, value, status}` 三键记录，`status` 为 `certain` 或 `review`，规范值是字符串或 null。只有确定且完全相同的规范值计为正确。header 路径为 `header.<role>`；流水路径为 `rows.<page>.<table>.<row>.<role>`，三个序号从零起，按实际来源的页面/表/打印行次序固定。不能按金额找最近真值、重排行、去重同额交易或取多个预测中的最佳值。

同一 header 字段的多页重复值经共享解析器核对相同后只输出一个字段，附完整证据列表；冲突须输出需确认，不能多数投票。多个表独立编号，多币种余额字段分别命名，不能跨资产抵销。

引擎可提供一个真实整行框及其原文。只有该行含字面 `|`，且表头恰好包含日期、币种、金额各一次及至多一个说明列时，才按可见分隔符和角色顺序解析；每个字段的证据仍是原整行框与原单元格文字，不均分字符宽度或虚构列坐标。格数不符的打印行保留行号，关键字段标为需确认；空槽和原始金额内部空格仍按既有严格规则处理。多词细框继续使用原几何路径，跨列、重叠框不能由整行模式补救。

明显表头样式含至少两个已知列角色，但缺列、重列或未知列时停止当前表，标记布局歧义。整行续表除下述页码与字段条件外，还须角色顺序完全相同、两个真实表头的左右边界分别相差不超过物理页宽的 1%；细框模式仍核对实际列中心，两种模式不能互相作为续表证据。该整行支持在正式识别前冻结，配置与共享解析器的实际摘要一并进入正式验收清单。

生成器须在 OCR 前冻结每种载体的几何/来源映射：PDF 的跨页流水仍为 page 0/1；竖向拼接照片为一个物理 page 0、table 0、连续 row 0–7。真值的字段路径按这个已知载体布局生成，映射不得传入解析器，也不得用识别结果修正。解析器只有在同一物理页上读到连续打印页码（如 1/2→2/2）、相同列标题且重复关键 header 无冲突时才识别续表；第二块未重复的字段沿用此前可见 scope，不要求票据再次打印全部 header。缺少连续页码或同列证据按独立表或需确认处理。独立原始输入测试必须证明两个相同列标题的独立表不会被误合并，连续页码也不能覆盖字段冲突。

## 门槛与 CER

令 T 为预期字段数，C 为正确字段数，E 为额外预测数，精确率为 C/(T+E)。缺失、错误或需确认均不正确；预期路径有重复预测时该槽全部不正确，后续出现计额外；未知路径每次均计额外。报告每份及每组的 T/C/E、待确认数、完整行比例和金额恒等式；恒等式仅作诊断，不能补齐或覆盖字段答案。流水的日期、币种、金额逐行属于关键字段，说明文字单独报告 CER。

全部冻结样本必须参与报告；崩溃、预算失败、超时的字段预测为 `[]`、文字为 `""`，不能漏掉分母。清晰文字层与清晰 OCR 分别聚合整数计数，不对百分比取均值。文字门槛 `C=T且E=0`；OCR 门槛 `100C≥95(T+E)`。先验证文字门槛；仅一候选达标就选它，两者均未达标立即停止。

两候选均达标时，令 D=T+E，用 `100×|C₁D₂−C₂D₁|≤2D₁D₂` 判定差距不超过两个百分点，此时选 Tesseract；否则选精确率更高者。不降低门槛、不删除困难样本、不将人工完成算作识别达标；正式结果不得反过来调配置、真值或解析器后继续声称同一次验收通过。

CER 只统一 Unicode NFC 与 CRLF→LF，保留大小写、内部空格和标点；以完整打印正文及固定行分隔为参考。逐文档报告编辑距离/参考字符数，同时报告微平均（总编辑距离/总参考字符数）和非空参考的宏平均。空参考不伪造分母，其插入字符仍进入总错误数并单列误报文档/字符数。正式热运行全部五轮完成并通过完整输出稳定性核验后，最终准确率与 CER 只取 round 0；输出不一致须报告并停止选型，不能挑最好的一轮或投票。

## 同机资源与测量

两引擎运行于同一 Linux 主机，使用同一渲染/方向纠正后的 raster 摘要，固定 CPU affinity 与单线程环境；Paddle small 型号、后端、精度、MKLDNN/HPI 等明确写入配置。记录主机 CPU/内存、OS/kernel、Python、引擎及所有模型/语言包版本、许可证、摘要。CI 主机结果不得冒充用户物理服务器性能。

正式配置采用相同的两个逻辑 CPU、4 GiB cgroup 内存、禁 swap、pids 128、每页墙钟 60 秒、启动 120 秒；记录容器/进程及既有图像预算。需要不同资源时在正式运行前修订冻结配置并两者一致，不静默给某一候选增加资源。内存、线程、页数等预算失败保留原结果；字段门槛始终不变。

冷启动各五次新容器进程，使用固定 D01 开发样本，不计入正式准确率；此处是进程与模型初始化的冷启动，不清除 OS 文件缓存。正式热运行各五轮×24 份 OCR，配对顺序固定 AB/BA/AB/BA/AB，A 为 Tesseract、B 为 Paddle；每个新进程仅用 D01/D02 开发样本预热，两个候选不会同时争用 CPU。另完整报告 12 份文字层、12 份退化和 8 类错误。保存全部原始单调时钟纳秒，按 nearest-rank `ceil(p×N)` 给出 p50/p95，主指标 N 包含全部已测终态请求和超时实际等待，成功子集另列且不替代主指标。

原始阶段日志分别记录模型核验、引擎初始化、原件读取、PDF 渲染、图片解码、RGB 转换及摘要、实际 SDK 调用、解析的真实开始/结束。`prepare_total` 是包含 SDK 消费的外层区间，不能与内部阶段相加；文字层探测与抽取也不能冒称纯渲染。只有实际成对事件进入阶段分布，未完成区间单列、不补零。IPC 包含在宿主从提交到完整返回的端到端区间中，不伪造独立 IPC 耗时；旧准备残差也不能冒充渲染时间。

“缺模型”引用同一宿主、同一 CI job、同一镜像的真实空模型负例，证明初始化前拒绝，并保留原报告摘要；其等待时间没有在正式请求中测量，故明确不进入延迟样本、不补零。“超时”在实际 SDK 调用开始、尚未结束时暂停真实容器，等待既定每页 60 秒截止；它验证受控超时与回收，是故障注入，不能称为模型自然运行超时。

宿主采样器以每 10 ms 为目标，保存实际每轮开始/结束及间隔，求同一采样窗口内进程 RSS 之和并取峰值；它是有实际窗口和间隔的采样值，不声称原子瞬时值或无遗漏峰值。另列 PID/启动时刻对应的各自 HWM，不能将不同时间发生的 HWM 相加冒充进程树 RSS。cgroup `memory.peak` 保留含 boot、文件缓存/内核的生命周期累计值，另列且不称为 RSS；CPU 时间、内存事件、观察失败和不完整样本均保留。测量在识别返回后、许可审计前结束。

[正式运行器](../../scripts/ocr_benchmark/formal_run.py)启动前只读核验 [冻结配置](../../tests/fixtures/ocr/formal-config.json)的源码精确清单、协议、原有锁、构建来源/许可政策、DEV 选择证据、全部模型和完整语料摘要；验证不得重新生成摘要。CI 在 DEV 配置验证及资源烟测之后运行，始终上传公开 JSON 与阶段 JSONL，私人 staging 在报告目录之外。五轮稳定性及上述文字/95%门槛全部决定最终选择；两候选均未达到 95% 时进程返回 1、保留完整报告并停止，不改配置、真值、解析器或门槛后继续本次验收。
