# OCR 同机验收协议 v1

本协议落实 [ADR 0019](../architecture/decisions/0019-local-ocr-worker.md)，字段计分实现为 [scoring.py](../../scripts/ocr_benchmark/scoring.py)。进度只见 [status.md](status.md)，实际制品摘要、环境、命令和结果留在对应 PR 与实测报告；本文不代表已运行引擎或已经达标。

## 语料与冻结顺序

[truth.json](../../tests/fixtures/ocr/truth.json) 是先于生成器与识别器逐项写定的独立真值：简中、繁中、英文、混排各三个模板，共八张发票/贷项/收据、四份流水。它保存字面正文、原始金额及规范字段，包含五种法币、负数、税额、千位分隔、重复同额交易和跨页、多币种流水。所有页面标明“虚构测试票据 / FICTIONAL TEST DOCUMENT”，组织、条目均虚构；不使用真实账单、账号或证件。

真值由开发助手手工写定，并由另一助手逐项审阅、用独立整数运算核对；不声称真人标注或由用户复核，不从 OCR 输出反推答案。后续生成器仅按真值排版，不计算识别答案；解析器不得读取真值。

| 分组 | 固定构成 | 用途 |
| --- | --- | --- |
| 清晰文字层 | 12 模板各一份文字 PDF | 金额、日期、币种关键字段精确率 100% |
| 清晰 OCR | 同 12 模板各一份扫描 PDF、一份照片，共 24 份 | 两候选分别达到关键字段精确率 ≥95% |
| 退化 | 旋转、低对比、模糊、透视各三份，共 12 份 | 报告错误发现和人工路径，不计为清晰样本达标 |
| 错误输入 | 损坏、加密、超页数、超像素、超流大小、缺模型、超时、已有乱码文字层八类 | 逐类验证有界失败；已有层不得改走 OCR |

清晰日期统一明确 ISO，不宣称清晰集包含歧义日期。退化组固定另含歧义日期 `01/02/2026`、只有 `$` 的币种、冲突重复合计各一例，预期必须标为需确认；其余字段仍逐项评价，不能将整张票据删除。已有乱码层另在错误组验证文字层优先。

排版固定 A5 420×595 pt、300 DPI，约 1750×2480 像素；两个跨页模板保持两页 PDF。照片将这两页按顺序竖向拼接成一个图像，不裁掉任一行，约 8.7M 像素；图片不从 metadata 猜 DPI。扫描 PDF 嵌入冻结 JPEG/DCT 字节，不能为容纳测试生成器的未压缩图像而抬高生产流预算。

先冻结真值和本协议，再完成独立的共享解析器、生成器及开发样本。开发样本与正式样本分离，不纳入上述 36 份；只在开发样本上选定一个 Tesseract 配置（包括 fast/best、语言、PSM）。在正式运行前提交全部正式输入/字体/模型/依赖/配置的实际 SHA-256 清单，固定随机种子 20261004，并证明同一 Linux 环境两次生成字节一致。未取得的制品不填假摘要。

## 共享字段解析与身份

worker 和 benchmark 使用同一解析器；输入只有实际文字、词框和页面几何，不能输入文件名、模板编号、样本编号、真值、预期字段列表或排版映射。保留候选文字、原始字段与证据。日期只接受无歧义 ISO，币种须显式代码；未知符号不猜。金额去合法千位分隔与显式正号、规范前导零及负零，规范值至少两位小数，仅删除第二位之后的末尾零；额外非零小数精度保留精确值并标需确认，不舍入。使用整数系数/尺度，不经 float 或默认 Decimal 上下文；不作 O→0 等模糊纠错。原始拼写始终留在证据中，确认财务命令另冻结用户最终选择的原始 JSON。

计分前输出 `{path, value, status}` 三键记录，`status` 为 `certain` 或 `review`，规范值是字符串或 null。只有确定且完全相同的规范值计为正确。header 路径为 `header.<role>`；流水路径为 `rows.<page>.<table>.<row>.<role>`，三个序号从零起，按实际来源的页面/表/打印行次序固定。不能按金额找最近真值、重排行、去重同额交易或取多个预测中的最佳值。

同一 header 字段的多页重复值经共享解析器核对相同后只输出一个字段，附完整证据列表；冲突须输出需确认，不能多数投票。多个表独立编号，多币种余额字段分别命名，不能跨资产抵销。

生成器须在 OCR 前冻结每种载体的几何/来源映射：PDF 的跨页流水仍为 page 0/1；竖向拼接照片为一个物理 page 0、table 0、连续 row 0–7。真值的字段路径按这个已知载体布局生成，映射不得传入解析器，也不得用识别结果修正。解析器只有在同一物理页上读到连续打印页码（如 1/2→2/2）、相同列标题且重复关键 header 无冲突时才识别续表；第二块未重复的字段沿用此前可见 scope，不要求票据再次打印全部 header。缺少连续页码或同列证据按独立表或需确认处理。独立原始输入测试必须证明两个相同列标题的独立表不会被误合并，连续页码也不能覆盖字段冲突。

## 门槛与 CER

令 T 为预期字段数，C 为正确字段数，E 为额外预测数，精确率为 C/(T+E)。缺失、错误或需确认均不正确；预期路径有重复预测时该槽全部不正确，后续出现计额外；未知路径每次均计额外。报告每份及每组的 T/C/E、待确认数、完整行比例和金额恒等式；恒等式仅作诊断，不能补齐或覆盖字段答案。流水的日期、币种、金额逐行属于关键字段，说明文字单独报告 CER。

全部冻结样本必须参与报告；崩溃、预算失败、超时的字段预测为 `[]`、文字为 `""`，不能漏掉分母。清晰文字层与清晰 OCR 分别聚合整数计数，不对百分比取均值。文字门槛 `C=T且E=0`；OCR 门槛 `100C≥95(T+E)`。先验证文字门槛；仅一候选达标就选它，两者均未达标立即停止。

两候选均达标时，令 D=T+E，用 `100×|C₁D₂−C₂D₁|≤2D₁D₂` 判定差距不超过两个百分点，此时选 Tesseract；否则选精确率更高者。不降低门槛、不删除困难样本、不将人工完成算作识别达标；正式结果不得反过来调配置、真值或解析器后继续声称同一次验收通过。

CER 只统一 Unicode NFC 与 CRLF→LF，保留大小写、内部空格和标点；以完整打印正文及固定行分隔为参考。逐文档报告编辑距离/参考字符数，同时报告微平均（总编辑距离/总参考字符数）和非空参考的宏平均。空参考不伪造分母，其插入字符仍进入总错误数并单列误报文档/字符数。多轮识别准确率只计一次；输出不一致须报告并停止选型，不能挑最好的一轮或投票。

## 同机资源与测量

两引擎运行于同一 Linux 主机，使用同一渲染/方向纠正后的 raster 摘要，固定 CPU affinity 与单线程环境；Paddle small 型号、后端、精度、MKLDNN/HPI 等明确写入配置。记录主机 CPU/内存、OS/kernel、Python、引擎及所有模型/语言包版本、许可证、摘要。CI 主机结果不得冒充用户物理服务器性能。

正式配置采用相同的两个逻辑 CPU、4 GiB cgroup 内存、禁 swap、pids 128、每页墙钟 60 秒、启动 120 秒；记录容器/进程及既有图像预算。需要不同资源时在正式运行前修订冻结配置并两者一致，不静默给某一候选增加资源。内存、线程、页数等预算失败保留原结果；字段门槛始终不变。

冷启动各五次新进程，使用固定开发样本，不计入正式准确率。正式热运行各五轮×24 份 OCR，配对 AB/BA 交替次序，每个新进程仅用两份固定开发样本预热；两个候选不会同时争用 CPU。保存全部原始单调时钟纳秒，按 nearest-rank `ceil(p×N)` 给出 p50/p95，主指标 N 包含全部终态请求和超时实际等待，成功子集另列且不替代主指标。报告初始化、渲染、识别/IPC、解析分别耗时；端到端从控制进程提交到完整返回，包含超时与失败计数，不混用不同阶段延迟。

每 10 ms 采样进程树并求同时 RSS 总和，取其峰值；另列父/子进程各自 HWM 与采样间隔。不能将各进程发生在不同时间的峰值相加冒充进程树 RSS；cgroup `memory.peak` 含文件缓存/内核，另列且不称为 RSS。CPU 时间和资源失败也须报告。

依赖、模型、字体在构建时取得并审核许可证，runtime 禁止联网下载；缺制品立即报稳定错误。候选环境分别锁定，不能因 Paddle 传递依赖变更默认 API 环境。完成正式对比及全部门槛后才将选中配置接入 worker；人工确认仍是独立 T05-4 步骤。
