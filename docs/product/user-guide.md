# Coinpup 中文使用手册

Coinpup 是按个人或公司分别建账的自托管记账系统。一个管理员可以管理多个独立账本，在网页上做完整账务，在受支持的原生客户端离线记简单收支。它不是多人审批、网银流水自动导入、交易下单、税务申报或开具法定税务发票的系统。

## 第一次使用

1. **先运行并初始化**：按 [README 的 Docker Compose 快速开始](../../README.md#docker-compose)启动 PostgreSQL 和应用、执行数据库迁移，并在服务器终端创建管理员。命令中的 `admin` 是示例用户名，密码由你交互设置；没有预设密码或公开注册。
2. **登录网页并创建账本**：可先建一个个人账本，以及每家公司各一个账本。填入地区、公司资料和本位资产，按需复制分类模板。模板复制后，各账本可独立维护分类；汇总时再映射到统一分类。
3. **建立账户并记期初**：在「账户」中添加银行、现金、信用卡、支付平台或加密资产账户，按实际持有的币种分别填写期初。不要把期初余额再录成一笔收入。
4. **录入第一笔流水**：选择正确账本、资金账户、日期、币种和分类；需要时按多个分类拆分，并在「票据与证件」上传、关联原件。在「流水」和「总览」复核原币金额与余额。
5. **先用虚构数据走通**：开始正式记账前，请完成受信 HTTPS、访问范围、数据库与附件备份和空目标恢复的验证。不要把开发环境直接暴露到公网。

网页在桌面和手机浏览器中均可使用，可切换中文/英文；切换不会翻译业务名称、说明或票据，也不改变账务数据。网页需要联网。带改密功能的版本可在「设置 → 修改密码」输入当前密码并确认新密码；改密后当前网页继续登录，其他浏览器或设备需用新密码重新登录。忘记密码时，由服务器运维人员按[会话与部署配置](../engineering/operations.md#会话与部署配置)交互重置；服务器 CLI 重置会撤销旧会话。

## 网页功能地图

| 在哪里 | 可以做什么 |
| --- | --- |
| **账本资料／账户／资产／分类** | 管理个人和多个公司的资料；维护不同币种的资金账户和原币期初；可选常用分类模板初始化，再维护各账本分类。账户可记录多币种，区分法币、原生加密资产及带网络标识的代币。 |
| **流水／总览** | 录入收入、支出、同币种转账、跨币种换汇与单列手续费；支持拆分分类、筛选、查看历史以及更正或取消已入账流水。 |
| **往来与项目／经营草稿／单据确认** | 管理客户、供应商、项目、收付款资料与经营单据；先编辑草稿，确认后形成经营收支和应收应付。按项目查看业务及已关联的实收实付。 |
| **经营收付／往来余额／贷项** | 登记实际收付款，关联和分摊到一个或多个未结单据，支持分次、适用的跨币种结算、分摊退回、退款和贷项，并保留往来与修订历史。 |
| **商业发票／周期Invoice** | 管理发票配置和编号，生成商业 Invoice、下载中英文 PDF 原件；周期规则生成待确认草稿，不会直接发行、发送给客户或视为已收款。 |
| **代付与偿还** | 可选开启同一管理员名下的主体间代付；双方账本各有独立记录，可分次偿还，费用只在受益方记一次。 |
| **票据与证件／识别与复核** | 保存私有原件，按归属账本查阅、下载、关联或归档。可选在自己的服务器启用 OCR worker，识别后进入人工复核；所有字段须核对，未确认不入账。 |
| **汇总与估值** | 选择个人、公司或主体组合；按原币、分类、期间查看，或用 USD、GBP、EUR、HKD、CNY 折算，并区分历史汇率和最新估值。原币金额不因估值改变。 |
| **结账与重开／提醒事项** | 控制已关闭期间并保留重开记录；按适用的地区规则或手动设置证件到期、年审和税务提醒。支持站内与邮件，邮件须由运维配置启用。 |

### 常见账务走法

- **登记链上资产时**，在「资产」中选择预设，或填写自定义代币的网络、合约和小数位数。核对并保存后，再在账户中勾选该资产。同名代币在不同网络上的余额分别记录。
- **从银行向信用卡还款**：在「流水」记同币种转账；先前刷卡消费已经是支出，还款不是第二笔支出。跨币种兑换用换汇，手续费另列。
- **一张单据分几次收款**：先建立往来与经营草稿，核对并确认单据；再在「经营收付」逐次录入实际收款并分摊。别把已确认的单据和对应到账流水各算一次经营收入。一笔 9 月归属、10 月收付的业务，在经营视角属于 9 月，在现金视角属于 10 月；两份统计不能相加。税额另列，管理口径不用于推定税务义务。
- **开商业发票**：选公司账本，配置编号、Logo 和收款说明等，填写客户、明细、币种、到期日和适用的折扣、税额，再检查并发行。需要更正并重新发行时使用新编号，旧编号及 PDF 原件仍可追溯。
- **上传票据或对账单**：上传 PDF 或票据照片后，可先保存为原件。如果本地 OCR 已启用，打开「识别与复核」，逐项确认主体、资金账户、日期、金额、分类及是否拆分，再决定是否入账。格式校验不等于恶意文件扫描，也不保证识别准确。
- **出错后更正**：已入账记录不做无痕覆盖或删除。用更正或取消保留原操作与冲销历史；遇到关闭期间，先核对是否应该重开。网络超时不代表一定没提交，先看流水或重试原操作，不要另录一笔。
- **检查总额或提醒**：保留原币；缺价显示缺价，不按零处理或假定稳定币与法币等价。估值所用报价看来源和时间，自动报价任务默认不启用。提醒日期应与实际税务或证件资料核对，站内记录与邮件投递均不是申报凭证。

## Android、iOS 与同步

- **Android 试用**：从[原生验收 PR](https://github.com/ygandwx/Coinpup/pull/454)或[原生移动端工作流](https://github.com/ygandwx/Coinpup/actions/workflows/native-mobile.yml)，寻找已成功运行的 APK 构建产物。验收 APK 保留 **7 天**，到期后须重新构建；它不是应用商店版本。已有 release APK 安装及模拟器核心流程证据，不等同于所有真机或公网上线验收。安装包登录需可达且证书受信的 **HTTPS** 服务地址。
- **iOS**：已验证无签名编译，不代表可以直接在 iPhone 上安装；发布签名、开发者账号和分发须另行配置。可以先用同一实例的手机网页。
- **先联网登录并同步**：输入自己实例的 HTTPS 地址，用同一管理员账号同步账本、账户、分类和报价。手机在断网时可编辑简单收支、查看已缓存记录、拍照或暂存票据。复杂流水的更正/取消、经营单据和发票等请用网页。换汇、转账和期初在手机上可查看已经缓存的记录，不要把它们当作完整的移动端记账编辑入口。
- **恢复连接后核对同步**：重试不会把同一笔重复入账；冲突会显示两边版本等待选择，不会默默覆盖。票据从已确认的偏移继续上传；应等服务器确认上传/同步后再清空应用数据。离线缓存不等于自动下载全部历史或备份。更细的构建和协议说明见[移动端 README](../../apps/mobile/README.md)。

## 安全、自托管与恢复

- **本地试用**：Compose 默认只在本机回环开放 Web 与数据库端口。服务器可先用 SSH 隧道；正式的远程地址应通过反向代理启用受信 HTTPS，精确配置 `COINPUP_ALLOWED_ORIGINS`（协议、主机和非默认端口），验证安全 Cookie。数据库和原件目录不要直接对外公开。
- **生产前核对**：部署所需域名/HTTPS、访问与防火墙、真实数据迁移、凭据、SMTP、应用分发与保留策略需另行确定。保持 `.env`、证书私钥、备份和原件私密；不能把测试验收视为某个生产实例已发布。
- **备份与恢复**：数据库保存账务，文件卷保存原件；只备份数据库不包含票据。使用 [数据库与原件 bundle](../engineering/operations.md#包含票据与证件的-bundle)，安排定期备份，演练还原到新建空数据库及独立文件目录，并核对原件、账本余额和同步记录再切换。不要用 `docker compose down -v` 停需要保留数据的实例。
- **遇到问题**：网页无法打开时先核对地址和证书，并由运维检查 readiness；Android 未同步先核对登录状态、服务地址、联网和待处理冲突。缺价、OCR 待核对或邮件未投递，请先检查对应配置和记录，不要重提交同一笔财务操作。
