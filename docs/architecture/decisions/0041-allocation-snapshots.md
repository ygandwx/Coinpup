# ADR 0041：分摊容量的事务快照

- 状态：已采纳（ADR0040的技术细化）
- 日期：2026-10-12

## 背景

Payment本金及已确认源行封存，剩余容量由不可变分摊行求和。写事务咨询锁能串行化提交，但REPEATABLE READ在等待锁前可能取得旧快照；锁后仍读取旧容量不能保证拒绝超额。[PostgreSQL 17事务隔离文档](https://www.postgresql.org/docs/17/transaction-iso.html)说明了此差异。

## 决定

- 新Allocation及其行只允许READ COMMITTED写事务，数据库INSERT守卫在通知和行写入前拒绝其他隔离级别，返回稳定约束`ck_business_allocation_isolation`。UPDATE/DELETE仍先返回原不可变历史错误。
- 后续结算服务在首条查询前明确设置该隔离级别，然后按咨询锁→账本→主体→完整排序资产集处理；不改变旧财务服务或只读REPEATABLE READ事务。
- 咨询锁保持至提交；延迟校验函数使用默认VOLATILE，在取得锁后的新查询快照中核对全组回执、Payment累计本金和所有目标源行累计含税额。分摊只追加，不维护可漂移的剩余金额缓存。
- 仍要求完整形状、精度、归属、日期和开放期间。成功原回执先重放，后续服务不因当前容量为零拒绝原成功意图。

## 影响

新增直接SQL检查及两个并发验收：第二事务先读旧容量，再与持锁事务竞争；同Payment与同源行分别只允许一个超额竞争者提交。只限制新分摊写入的内部事务方式，不改变产品金额、历史、API或旧命令语义。

## 备选方案

不依赖部署者恰好保留数据库默认隔离级别；仅锁未更新的Payment行不能刷新旧快照。暂不支持SERIALIZABLE混用，因为容量正确性不应依赖所有调用者正确处理另一种重试协议，也不引入可变财务事实只为制造写冲突。
