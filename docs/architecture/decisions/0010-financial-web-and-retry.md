# ADR 0010：网页财务录入与待确认提交

- 日期：2026-10-03
- 状态：实施中；执行证据见 [项目状态](../../engineering/status.md)
- 范围：T04-2，基于已集成的 T02/T03 财务 API

## 背景

结构工作区已经能管理独立账本、账户、分类和原币余额。财务网页必须保留金额精度，并处理“服务端成功提交，但浏览器未收到响应”的情况。直接重新生成幂等键可能重复记账，浏览器刷新后凭空恢复未保存的草稿也没有可靠依据。

## 决定

### 原币录入与流水

提供期初、收入、支出、同资产转账和实际换汇五类表单。金额和日期按 API 字符串提交；金额校验和拆分求和使用 BigInt，禁止转成浮点数。期初可正可负且非零，其余本金、拆分和费用为正。收支拆分分类不能重复、合计必须等于本金；每项费用独立指定账户、资产和支出分类。转账使用不同账户和同一资产；换汇使用不同资产，可以同一账户。

只显示当前账本有效账户、资产关联和分类。失效的引用仍能在历史流水中显示，服务端负责最终余额与所有权校验。流水按当前 `OperationState` 读取，明确展示取消状态及当前版本；历史新增回执不能替代当前状态。不汇总不同资产，也不把换汇本金或信用卡还款计作费用。

### 一个待确认命令

`PendingCommandController` 在 App 实例内存维护单个未解决命令；不放入 localStorage、sessionStorage、URL 或日志。首次有效提交冻结 owner ID、账本 ID、操作 UUID、幂等键及完整 JSON 正文。重复点击共享一次请求。重试从固定正文恢复，不重新读取可编辑表单，也不改变原始金额字符串。

网络中断、超时、服务端错误或无法验证的成功响应都保留未知状态。此时暂停新记账和账本切换；可以手动以原命令重试，或按操作 UUID 查询已持久化的当前状态。查询 404 可能与原提交竞争，不能据此生成新命令。幂等内容冲突需要核对，不能自动换键。

明确拒绝且此前没有未知结果时，允许修改草稿后以新命令重新提交。已经出现未知结果的命令，即使后续请求遭到拒绝，也保留原命令，避免把临时拒绝误认为原提交没有生效。

### 认证与生命周期

401 后隐藏工作区和命令内容，内存保留待确认命令。重新登录按不可变用户 ID 核对；同一用户只能手动继续，不能自动发送。不同用户或主动退出清除内存状态并令迟到结果失效。令牌不保存在控制器中，每次请求使用当前会话的 CSRF 值。

刷新或关闭网页会丢失内存状态；未知提交时显示明确提示并注册离开提醒。离开后应先查询流水，不宣称网页已经支持持久离线队列。离线持久同步留给 T11/T12。

### 资产目录

全局目录允许显式添加法币或支持的加密资产，及启停现有定义。代码、网络、代币标识和精度创建后不修改；稳定币不自动猜测网络或精度。停用阻止新入账，历史数量及账户余额保留。

资产结构写入使用独立的版本合同，没有财务幂等回执。未知创建结果须先读取目录核对相同身份；不能套用财务命令回执。账户必须另行关联新资产后才能入账。

## 验证与边界

控制器测试覆盖精确正文、双击、服务端已提交后丢响应、401 同用户恢复、不同用户隔离、迟到结果、无效成功响应和 404 核对。真实浏览器通过容器 API 验证拆分收支、信用卡还款、换汇第三资产费用及稳定币配置；丢响应测试先让真实 API 完成提交，再丢弃浏览器响应。具体执行结果以状态文档和 CI 为准。

本增量尚未提供网页更正、取消和分录历史操作，留给 T04-3；当前流水可以显示由已实现 API 更正或取消后的状态。文件上传、行情估值及多主体汇总继续依照原任务边界实现。
