# ADR 0034：周期规则网页提交恢复

- 状态：已采纳（技术细化）
- 日期：2026-10-10
- 依据：ADR0025、0031、0033；不增加财务命令或产品范围。

## 背景

规则保存和后台生成都会推进规则版本。响应丢失之后，当前名称、归档状态或源草稿版本即使与请求相同，也不能证明本次修改已成功。周期实例的原生成证据和可编辑的当前草稿必须分别展示。

## 决定

- 使用独立的PendingRecurringController，沿用既有经营草稿恢复状态机，不改现有金额/财务控制器。每次提交冻结所有者、账本、规则ID、动作和完整JSON正文；重试原请求，CSRF使用重新登录后的当前令牌。
- 创建使用稳定UUID。未知创建结果遇到重复ID时读取同账本同ID；只有版本1、进度0、名称、时区、起点、周期/间隔和源ID/版本完全匹配才确认。任一后续修改或生成导致版本变化时按冲突处理，不覆盖现有规则。
- 名称/模板刷新和暂停/恢复携带原expected_version。成功的直接响应必须匹配预期下一版本和请求字段；未知提交后的更高当前版本只能证明存在变化，不能证明本次提交，因此显式显示冲突。读取失败保留未知状态，不自动更换版本或创建新规则。
- 提交中和未知状态禁止重复新意图与账本导航；401隐藏私人数据，同一所有者重新登录后手动恢复。更换用户或主动退出清除意图，迟到响应不能恢复已退出数据。原JSON和模板只保存在页面内存，不写浏览器存储或日志。
- 规则页面显式显示时区、下个计划日期和暂停状态，说明恢复会从首个未生成周期补齐；不以浏览器当地日期推断任务是否已运行。改变起点/周期/时区须暂停旧规则并新建，刷新源模板是单独的显式操作。
- 读取实例按序号分页，展示原生成日期/规则版本并链接当前草稿；人工编辑草稿不会改写实例。任务仍由jobs维护入口调用，页面不提供越过日历到期判定的生成请求。

## 影响

先提供类型化API封装、原意图控制器和单元测试，再接双语页面及桌面/375/320验收。测试涵盖重复点击、响应丢失、401与原意图重试、后台推进导致版本冲突、读取失败、用户切换和迟到响应；最终以真实浏览器和数据库恢复证据验收B-14。

## 备选方案

只读取当前字段容易把另一笔并发修改或任务生成误认为本次成功；把expected_version自动改成最新版本会静默覆盖他人工作。保留原意图并显式解决冲突，与既有草稿协议一致。
