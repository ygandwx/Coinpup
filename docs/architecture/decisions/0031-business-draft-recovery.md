# ADR 0031：经营草稿网页提交与恢复

- 状态：已采纳（技术细化）
- 日期：2026-10-09
- 依据：ADR0025、0029、0030，T06-2；不新增财务业务规则。

## 背景

整单保存包含多行和派生金额，响应丢失后不能只比较记录ID，或把读到的相似内容当成本次修改成功。

## 决定

- 专用内存控制器冻结所有者、账本、单据UUID、create/save/archive动作、完整请求JSON以及所选资产身份/精度。一个意图只有一次在途请求；普通重试不改UUID、版本、行顺序或金额拼写，CSRF使用当次会话值。
- 不写浏览器持久存储或日志；未解决意图限制主体切换及导航，语言切换只改变文案。401隐藏私有内容，同用户重新登录后手动恢复；换用户或主动退出清除意图，代际标记隔离迟到响应。
- 写入成功响应必须匹配归属、身份、预期版本、动作、原输入和方案A金额。新建校验版本1及首次行顺序；整单保存按稳定行ID比较输入，保留服务器历史序号。描述只按既有Python去首尾空白规则比较，金额字符串不改写。
- 创建重复ID，或此前结果未知后重试受归档/停用等限制时，允许读取同账本同ID核对。只有版本1、原输入和精确结果相同才显示已核对成功；已变更记录进入待人工核对冲突。读取404或失败不能证明原提交失败，继续保留意图。
- 整单保存及归档/恢复遇到版本冲突后读取当前记录。若此前结果未知，只有读到同身份且更高版本才解除待提交锁并进入冲突；绝不把内容相似视为本次修改成功。用户显式载入当前版本后才可创建新意图。
- 冲突读取可以返回更换过资产的当前草稿，不能用旧意图的精度判定当前记录无效；旧资产精度只用于本意图的成功核对。
- 完整保存和归档仍沿用原API及事务版本协议，不增加永久财务回执。确认/结算后的状态与回执在后续财务命令中实现，并须保留更高版本记录的可读性以完成冲突核对。

## 影响

先交付API封装、响应核对和提交控制器，再接双语界面。覆盖响应丢失、精确原意图重试、重复点击、无效成功响应、旧版本冲突、读取失败、401和迟到响应；界面随后做中英和三种宽度验收。

## 备选方案

自动换ID/版本会掩盖重复提交或覆盖并发修改；仅凭记录存在或字段相似无法识别某次更新是否成功。采用已有资料编辑协议，补充整单与金额核对。
