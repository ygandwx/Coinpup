# ADR 0029：经营草稿创建与读取协议

- 状态：已采纳（技术细化）
- 日期：2026-10-09
- 依据：ADR0024–0028、T06-2，用户批准计价方案A；本决定不涉及确认后的税额统计。

## 背景

草稿表头和行已具备精确计价与归属约束，需要应用层原子创建和快照读取，供后续编辑与网页使用。

## 决定

- 客户端生成稳定的整单/行 UUID，提交可编辑原始字符串；不接受派生金额、资料快照、状态、归属或版本字段。
- 事务按咨询锁→账本→主体→资产顺序执行，校验资产可用、同账本资料未归档、客户/供应商角色和分类方向；一次提交保存表头、行和变更通知。草稿不生成财务操作或回执。
- 重复创建返回现有重复记录冲突，不覆盖也不伪装成财务幂等重放。未知结果按稳定ID读取，核对版本和原意图；后续网页冻结原请求并使用ADR0025的恢复原则。
- 服务按ADR0026重算金额，行序号按首次提交顺序分配。输入字符串原样保存，派生金额按资产精度输出；输入回显不改写成规范金额文本。
- 主体快照只含ID/版本、名称、法定名称、国家/地区、公司类型；往来快照只含ID/版本、名称、角色、法定名称、邮件、电话、地址、税号。分类含ID/版本、中英名称和方向；项目含ID/版本、名称。内部备注和主体自定义详情不复制。
- 快照由服务器白名单生成，不会随资料更新自动刷新。Invoice打印所需公司展示资料在T06-6细化；不默认公开内部详情。
- 详情在同一只读快照事务中返回表头、未归档行和精确合计，并核对已存金额与原始计价一致；不一致报错，不自动修复。
- 已保存草稿允许在资料归档或资产停用后读取。可用性只约束新输入，读取不依赖当前资料名称、角色或状态。
- 列表默认含归档，按创建时间/ID升序，沿用1–200条及offset上限；用分组合计和资产批量查询，避免逐单读取行。匿名历史身份不出现在经营草稿列表/详情中。

## 影响与边界

- 本包只有创建/读取服务和恢复验证，不增加公开HTTP接口、迁移或财务命令；编辑、API和网页顺序接续。
- 编辑将校验父版本并只递增一次，保留稳定行身份，删除用归档表达，刷新快照须显式；不能把本包创建重试当成更新。
- 原金融API、永久回执、期间锁及历史语义保持。确认后的含税/未税经营统计仍待用户选择，不影响草稿计价。

## 备选方案

客户端提交合计和快照会扩大信任边界；逐行独立保存会暴露半张单据；把当前资料联表当历史快照会使旧草稿随改名变化，因此均不采用。
