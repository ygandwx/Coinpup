# ADR 0013：票据网页与上传恢复

日期：2026-10-04。任务：T05-2。状态：实现中，验证与暂停点见[当前状态](../../engineering/status.md)。

## 交付边界

网页提供独立账本的票据目录与公司证件原件入口，支持 PDF/照片上传、下载、标题编辑、文件归档与恢复。流水的 Files/票据入口查看证据，也可上传新原件或关联账本已有文件；流水更正或取消不移除关联。文件归档和关联归档各自保存版本，归档主体只读。此处不实现 OCR、提醒或自动费用识别。

沿用 [ADR 0012](0012-private-files-and-consistent-bundles.md) 的两步上传协议。浏览器保留同一 File、稳定上传 UUID、冻结元数据、账本和可选流水 ID；重试必须原样发送。JSON 请求维持原短超时，原始文件 PUT 使用服务器上传时限加传输余量，Cookie/Origin/CSRF 与同源路径限制仍然生效。

## 待确认上传

应用顶层的控制器只在内存保存上传意图；File 不出现在公开状态快照，也不写入 localStorage/IndexedDB。只有已确认或明确拒绝才能释放当前意图；网络错误、超时、停止传输及丢失响应保持待确认。Stop 只中断客户端等待，不能表示服务器撤销保存。

`GET /uploads/{id}` 只有返回相同冻结预留元数据、ready 状态及匹配完成回执才可确认。pending、404、无法解析或身份不符均不能证明失败，也不能生成新 UUID 覆盖未知请求。已知内容冲突始终保留，包括核对时 401、同用户重新登录后的查询，不能用匹配文件名/大小掩盖字节冲突。

401 时隐藏原件及元数据；同一用户重新登录后恢复到原账本/流水上下文，由用户手动重试或核对。换用户或明确退出则释放原文件并忽略迟到响应。待确认时锁住导航，并提示刷新或关闭将丢失内存里的原文件；若已离开，应先核对目录再重新选择。

## 元数据与下载

标题编辑冻结原版本；冲突保留草稿，显式重新载入当前文件才更新标题和版本。文件/关联归档以预期版本提交，不静默覆盖并发变化。目录、关联与候选原件分别分页，读取在上下文变更时中止。

下载经鉴权 API 取得 Blob，并检查实际大小、媒体类型及 SHA-256，再创建短寿命 ObjectURL 触发浏览器下载，及时释放 URL/请求。上传成功保留单独的原件下载入口，即使复用了归档原件或文件不在当前页，也能取回原件。

## 验证

控制器单测覆盖固定请求重试、停止、失联、同用户恢复、异用户隔离、冲突与不完整响应。真实桌面/手机流程覆盖 PDF/PNG 字节、账本隔离、标题冲突、证据与金额独立、归档下载，以及服务器已提交但响应丢失后的确认。浏览器路由中止不等于证明服务端收到了部分字节；实际流中断边界由后端 ASGI 与存储测试负责。

本地虚构数据视觉检查覆盖 1440、375、320px，检查长标题、原文件名、双语草稿、上传待确认和归档状态。真实 CI 和具体计数只记录在状态文档及对应 PR。
