# ADR 0035：版本化提醒规则与日期依据

- 状态：已采纳（技术细化）
- 日期：2026-10-10
- 依据：P-07、C-08/C-09、架构第7节；不改变财务命令或统计口径。

## 背景

公司注册资料已具备，但地区、州、公司类型、财政年度和证件有效期对应不同事项。单凭成立日期推断所有义务，或把周期Invoice的月底规则用于法定期限，会产生错误截止日。

## 决定

- 在`coinpup_api/reminders/`先建立不访问数据库、网络或系统时钟的日期评估内核。规则由随版本发布的受审目录提供，不接受任意表达式、脚本或运行时抓取法规。
- 每条规则固定ID、版本、地区/州、公司类型、所需参数、官方来源及核验日期。来源与实施边界唯一记录在[规则目录](../../product/reminder-rules.md)。更改公式、适用条件或节假日日历须新版本，旧规则及旧评估依据保留。
- 调用方显式提供公司资料、目标报告年度或实际报告期末、必要证件日期及适用性确认。地区匹配仅筛选候选规则，不等于确认纳税/申报义务；`applicability_confirmed`必须显式为真才能给出可采用的推算结果。
- 结果区分`calculated`（参数及本规则依据完整）、`missing_parameters`、`needs_verification`和`not_applicable`，返回稳定原因码、输入快照、规则版本、核验日期与推算日期。未知规则版本拒绝执行，不静默选择最新版本。
- 未核验规则、未知节假日年份、闰日周年解释不明或其他未覆盖特殊条件返回`needs_verification`；可附基础日期用于解释，但不能把它当已确定截止日或自动启用投递。缺参数列出字段；明确不匹配的地区/类型和报告年度返回`not_applicable`，不推断“没有其他义务”。
- 日期用显式`date`，不以UTC/浏览器时区截取；投递另存IANA时区、当地提醒时点及提前天数。成立当年、跨年、闰年、月份末尾和日期溢出分别测试；不共用Invoice周期日历的默认截断行为。
- 人工日期与系统推算值分开保存；带理由的覆盖优先，规则重算保留覆盖值及原记录。评估纯函数不写历史；后续持久化采用账本归属、版本条件更新和追加审计，接入变更日志与完整恢复。
- 年审/税务/证件事项可由人工日期驱动；未确认规则须用户明确确认或人工设定后才能启用提醒。自动评估不产生分录、不分配Invoice编号，也不修改期间锁。

## 影响

按依赖拆分：来源和纯日期评估 → 同账本事项/覆盖历史模型及迁移 → 服务/API与恢复 → 站内提醒/邮件投递 → 双语网页和C-08/C-09验收。公司/证件部分只依赖现有主体资料；经营单据提醒待有效单据和结算模型稳定后接入。

投递沿用jobs入口、PostgreSQL唯一键（事件、渠道、计划时间）和标准库SMTP。发信不持业务锁；成功投递不重发。SMTP接受之后丢响应无法仅靠数据库保证外部恰好一次，投递协议须先细化“结果未知”的可见状态及人工核对，不能把不确定结果静默当失败重发。

首批实现只启用目录中证据足够的公式；其余规则明确待核验，仍允许人工日期。验收使用虚构公司/证件及测试时钟，C-08的R-v1/R-v2仅为测试规则，不能作为任何地区法规的证据。

## 备选方案

一个全球“周年加天数”公式无法表达财年和地区差异。自动抓取并执行法规超出既定范围。每次规则更新覆盖人工日期会丢失用户/会计判断；保留独立覆盖和完整版本依据更符合P-07。
