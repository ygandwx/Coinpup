# ADR 0011：网页更正、取消与版本历史

- 日期：2026-10-03
- 状态：实施中，执行证据见 [项目状态](../../engineering/status.md)
- 范围：T04-3，复用 [ADR 0008](0008-operation-revisions-and-cancellation.md) 的后端修订合同

## 决定

### 明确的替代内容与版本

流水卡片提供更正、取消和版本历史入口。更正从 `OperationState.latest_posting` 白名单复制完整请求字段，保留原始金额、日期、分类拆分和所有手续费；不复制业务 ID、账本 ID、凭证 ID 或响应时间字段。业务类型固定，期初的账户与资产固定。无效的旧引用保留名称/标识供核对，不静默替换或删除；新替代内容仍须满足有效引用校验。

打开表单时冻结外层 `OperationState.version`。原因经去除首尾空白后必须为 1–1000 字符。另一窗口修改后，旧版本返回 409，表单草稿保留；用户明确重新载入当前记录才替换预填数据和版本。取消只提交版本与原因，可以冲销已失效的旧账户/分类引用，且不能重新激活已取消记录。

### 修订与新增的重试区别

修订继续使用既有业务 ID，每次新意图只生成新的幂等键。控制器区分新增、更正、取消动作，固定完整正文与版本。原新增回执、原修订回执和最新查询状态分别保存，不用历史回执覆盖当前状态。

新增命令查询到其新 UUID 可以证明该业务已落库；修订的业务 UUID 在提交前已经存在，因此查询旧版本、相同版本或更高版本，都不能单独证明本次修订成功。修订的“核对记录”只显示当前版本，继续保留待确认命令。成功确认来自原 POST 使用原幂等键取得的回执；确认后重新读取当前流水与余额。

允许一种明确失败后的安全恢复：原键 POST 返回真实 `version_conflict`，随后查询到当前版本严格高于冻结版本。后端在同账本串行锁下先查询永久回执，再校验版本；若已有本命令成功回执就会先返回它，而版本只能递增。上述两个证据共同表明旧命令不能再成功，可以解除待确认锁并要求用户重新审阅。单独 GET、无明确错误码的 409、可逆的归档拒绝都不满足此条件。

### 可追溯的历史

历史按版本升序分页展示首次入账、更正和取消、原因、记录时间及执行人标识。每个版本展开其入账与冲销凭证，展示交易日、业务归属日、账户/分类、资产及带符号的精确金额。费用组件保留原顺序和符号；页面不重新推算或改写已封存分录。

已取消记录保留原内容及全部历史，更正/取消按钮停用。账本归档暂停新命令，历史仍可查。

## 验证与边界

单元验证覆盖修订原键重放、历史回执与当前版本分离、GET 不误确认、严格冲突恢复、完整替代内容及身份隔离。真实浏览器通过桌面和手机执行 100→120→取消、ETH 最小单位手续费冲销、双窗口冲突保留草稿，以及提交前/提交后丢响应后只执行一次修订。具体结果见项目状态与 CI。

T04 覆盖联网的手动记账闭环；票据附件、经营单据、汇总估值、提醒和 App 继续按原路线图实现。跨任务验收案例中的附件上传与恢复部分不得因手动流程完成而提前标记通过。
