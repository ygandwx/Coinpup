# ADR 0032：周期 Invoice 的日历与草稿实例

- 状态：已采纳（技术细化）
- 日期：2026-10-09
- 依据：P-03/P-06、B-14、T06-6；只处理草稿，不决定确认后的税额归属。

## 背景

周期实例必须能在任务重试或恢复后得到相同身份；月底按上一期日期继续加月会逐步偏离用户原先选择的日期。

## 决定

- 日历输入为明确起点日期、日/周/月/年单位、1–120的整数间隔，实例序号从0开始。序号使用非负32位整数；日期超出1–9999年必须显式报错，不能回绕、跳过或改成其他日期。
- 每个日期都从原起点计算。月/年按目标月保留原日号，目标月无此日时取月底；下一期继续从原起点计算。例如1月31日逐月得到2月末、3月31日；2月29日逐年到非闰年用2月28日，闰年恢复29日。
- 周等于7个日历日；不把一个月当作30天或一个年当作365天。日历函数不访问当前时钟、不推断时区；后续规则显式保存IANA时区，由任务把有时区的当前时刻转换为该地日期后判断是否到期。
- 每个规则UUID和实例序号经固定命名空间UUID5生成单据ID；每条模板行UUID在实例单据命名空间中生成行ID。规则或实例不同则身份不同；重试不重建随机身份。
- 模板为已校验的Invoice草稿输入快照，原数量、单价、折扣和税率字符串保持不变；不接受bill模板。新单据日期为本次周期日期，到期日和各行归属日期保持相对模板单据日期的日数差；不把所有行改成同一天。任何日期平移溢出都拒绝整张生成。
- 创建实例仍走同账本引用验证和方案A服务器计价。稳定UUID只是身份，不是提交证明；正式生成必须以数据库唯一实例记录与草稿原子提交为依据，不能仅凭一个同ID草稿存在宣称已执行。
- 生成只产生草稿，不入应收、收入或现金，不分配正式Invoice编号，不发送客户邮件。已生成草稿与后续模板修改相互独立。

## 影响

先交付无数据库/时钟依赖的日期与输入投影及边界测试；规则持久化、时区、唯一实例、任务、API、网页及恢复验证分别在后续工作包落地。它们仍须遵守咨询锁→账本→主体→资产锁序和同事务变更日志；不能把日历函数当成已运行的周期任务。

## 备选方案

按上一期月底继续递推会漂移；每次使用随机ID会增加重复草稿风险；直接确认或分配正式编号超出周期草稿的既定边界，因此不采用。
