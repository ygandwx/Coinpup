# ADR 0062：设备同步、冲突证据与附件续传

- 2026-11-25，提议（T11 服务端与 T12 客户端契约）。
- 依据 [P-08](../../product/requirements.md)、[D-02 至 D-05](../../product/acceptance.md)、[ADR 0012](0012-private-files-and-consistent-bundles.md)、[ADR 0014](0014-versioned-command-hashes.md)、[ADR 0015](0015-ordered-change-log.md) 和 [ADR 0021](0021-ocr-confirmation-transactions.md)。

## 背景

离线设备可以在上传途中断开，也可以在另一台设备修改同一记录后提交旧版本。恢复较早快照后，同一通知序号可能对应不同事实，客户端仍持有当时的原始写入意图和附件。

## 决定

- 每台设备以客户端生成 UUID 登记在当前会话所有者下。UUID 只标识同步设备，访问继续依赖会话认证、写入保护与账本归属。登记可重放，退役保留历史并阻止新的设备写入。设备登记与页确认属于协议元数据，独立于业务通知流，避免一次确认产生下一次确认。
- 首次读取先在登记项下保存所有者的已提交起点和完整通知证据，再读取当前资源并补读该起点之后的通知。增量页在固定上限内从原游标读取，序号与游标用十进制字符串。设备持久化整页后提交原页和前一条通知的证据。服务端在同一事务校验设备、已保存进度和实际交付序列。完整通知证据包含所有者、账本、对象身份、版本、动作和带时区的时间。空页保留原游标，已确认页重放原回执，迟到页保留新进度。
- 发现回滚点后的证据缺失或同号异证据时，暂停该设备增量提交。客户端保留原意图、原幂等键及附件。重新核对服务端资源和原命令回执后，以新的设备登记 ID 显式建立新同步链，保留原登记与确认历史。服务器可见的页确认只证明接受该页证据，财务回执与附件完成各自有独立状态。
- 每次推送仅接收一种白名单业务命令和一笔稳定意图。服务端先核对设备、授权与原推送回执。新意图还需匹配该设备的已确认通知证据，然后按账本范围调用既有命令。绑定同一个外层事务，沿用咨询锁、账本、主体及资产的顺序。向财务命令传入原嵌套 JSON、已有账本幂等键及稳定对象 ID。提交业务及两种回执同成同败，重放早于版本或归档检查。金额字符串、逐资产配平和历史封存由原命令验证。
- 版本冲突保留经类型约束的离线命令、它依据的不可变业务版本及实际竞争版本。冲突作为独立结果提交，不产生分录。对照区分固定的双方证据与后来读到的当前版本。选择保留当前记录可确认该冲突；选择离线意图时，用户以最新预期版本和新键显式提交原业务命令。已取消财务对象是同 ID 的永久终态；向旧版本的更正、取消或重用创建 ID 均沿用原命令的拒绝保护。
- 附件续传沿用原上传 UUID、归属、类型、总长与完成回执。以原件 SHA-256 固定该上传的续传内容。一次提交一个有界字节段，以已提交的连续字节数为下一起点；原段重试应核对偏移、大小和摘要。段与进度保存在数据库，随 bundle 恢复。完整内容由现有文件校验和发布流程核对总长、摘要与类型；引用、可下载原件及完成回执提交后才释放暂存段。文件状态独立于财务推送、设备页确认和 OCR 人工确认。

## 影响

依次交付设备登记与有证据的拉取、版本化财务推送与冲突、附件续传三个可独立验收的接口包。每包最多一个迁移、一个迁移 PR 在途。各包生成 OpenAPI，保留既有 Web 命令和整文件上传契约。测试覆盖两台设备互不推进、同号异证据、原命令重放仅入账一次、双方版本只读对照、取消传播、两次中断及空目标恢复。

## 备选方案

全量覆盖或无条件使用服务器最大序号会跳过未读通知。先调用财务命令再写推送回执会增加无法原子核对的间隙。单凭附件文件名或分段长度确认续传会允许不同内容复用原上传；续传以原件摘要和已提交字节段为依据。
