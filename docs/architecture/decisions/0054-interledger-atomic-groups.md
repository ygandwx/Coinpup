# ADR 0054：跨账本代付与偿还的原子关联

- 日期：2026-11-25
- 状态：采用，用户选择方案 A。

## 背景

代付涉及付款主体与费用归属主体。按 [C-08 与 P-04](../../product/requirements.md)、[B-09 与 B-10](../../product/acceptance.md)及 [ADR 0016](0016-account-classes-and-dimensions.md)，两边各自配平，费用只由受益方确认。关联还要为部分偿还、审计与汇总提供明确依据。

## 决定

- 所有者级代付关联绑定同一所有者的两个不同账本。每个账本的成员操作通过操作与账本的复合外键绑定，账户、分类与凭证仍由所属账本约束。使用现有往来控制账户及对方主体维度。原代付及每次偿还都保存两方的已封存凭证身份，共用原代付关联 ID，原始日期、资产、金额与成员不可变。
- 同一事件的两个账本使用同一个完整资产 ID，以最小单位计算金额。偿还引用原代付，日期不得早于代付，金额须为正且不超过未结本金。未结金额由原本金减去已提交的偿还累加值推导。

| 事件 | 原付款方账本 | 受益方账本 |
| --- | --- | --- |
| 登记代付 | 资金账户减少，应收对方往来增加 | 费用增加，应付对方往来增加 |
| 登记偿还 | 资金账户增加，应收对方往来减少 | 资金账户减少，应付对方往来减少 |

- 两侧同一事务提交。先取 [ADR 0015](0015-ordered-change-log.md) 的写事务咨询锁，再锁排序后的所有参与账本、排序后的主体、排序后的涉及资产，最后锁关联及相关业务行。两侧均校验权限、归档、期间及本地引用；复用既有原币配平和封存约束。提交时校验两侧成员、归属、资产和金额。凭证、未结事实、变更通知和回执一起提交，任何一步失败都整笔回滚。后续若提供更正或取消，须沿用整组冲销并核对有效偿还。
- 关联写入使用独立的所有者级幂等键空间。按 [ADR 0014](0014-versioned-command-hashes.md) 冻结 v2 动作、固定路由、参与身份、路径中的原代付关联及完整请求正文。经认证的原调用者用同键同行为重放永久原回执，同键不同请求返回 409。回执匹配优先于当前开关、归档、期间和剩余额校验。网页重试提交同一冻结请求及原键。
- 功能按所有者选择开启，初始关闭。关闭时暂停新代付和新偿还，历史与回执仍然可读可重放；重新开启可继续尚未结清的业务。主体归档与结账沿用现有写入规则。

## 影响

- 通过原代付关联追溯每次偿还及两边凭证。双方均纳入汇总时，可通过明确关联识别内部偿还，外部代付及受益方费用仍完整计入；单方视图保留自己真实的资金变化。
- 新表随通用 bundle 备份和空目标恢复，有已保护历史时拒绝降级。验收覆盖个人代公司、公司代公司、分次偿还、仅受益方费用、两侧归零、同键原回执、整笔回滚、越权或超额拒绝及关闭后历史。

## 备选方案

两侧分开提交依赖事后补偿，读取、恢复与重试可能看到半笔业务。手工备注或等额匹配缺少可验证的偿还链路，无法区分内部偿还与对外付款。
