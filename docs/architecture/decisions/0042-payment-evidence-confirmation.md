# ADR 0042：银行/OCR原件关联已有经营付款

- 状态：已采纳（T06-5技术细化）
- 日期：2026-10-13
- 依据：需求P-03/P-08、验收B-05，ADR0012/0021/0040及用户本轮指令。

## 背景

已有Payment与Allocation记录真实收付及结清关系。再次上传银行原件必须选择原付款，只添加证据。旧OCR确认的operation字段是五类财务命令回执；Payment有独立身份、原本金操作及可空的完整初始分摊回执，不能冒用旧字段或再次调用收支命令。

## 决定

- 在既有OCR确认请求中增加明确的entry分支：`kind="link_payment"`、payment_id及expected_version。版本指所选原付款的FinancialOperation版本；原OCR草稿版本仍由外层expected_version控制。客户端明确选付款并核对账户、资产、本金、交易日与独立费用，不按识别金额、日期或描述自动匹配。
- 增加只读`GET /api/v1/ledgers/{ledger_id}/business-payments/{payment_id}/evidence-target`，返回既有付款详情及当前操作版本/状态供审阅；付款详情原GET和原回执结构不改变。读取保留归档历史，核对账本归属、原付款/原凭证身份和完整初始分摊回执，响应no-store，不读取私有目录或取得写锁。
- 同一确认POST与历史GET增加独立action="link_payment"回执分支，封存payment完整原BusinessPaymentResponse及operation_version，同时保留原intent_id、draft_id、ledger_id、draft_version、target_ledger_id与target_file_id。旧create/link回执仍只含原operation字段，JSON和v2摘要不变；按action选择完整schema，不给旧回执补payment:null。
- 继续使用原intent_id和固定路由的v2原JSON摘要，数组顺序、金额拼写、字段省略及null的区别不变。永久回执重放先于当前草稿状态、版本、归档、期间及付款状态；新请求检查expected_version和active操作，未知结果只重放原正文/原意图，不依据已存在文件或当前余额推断成功。
- 全部OCR字段按ADR0020人工确认；文字层按原策略预填。复用已审阅字段/来源行、重复提示及明确duplicate_ack。原件和目标原件必须同内容（摘要、长度、媒体类型），均由同一所有者持有；跨账本沿用显式复制并选择目标原件，不把文件归属直接转移。
- 关联事务只写文件关联、封存OCR确认、草稿确认状态及同事务变更日志。不得调用财务创建/修改命令，不新增或改动FinancialOperation、Journal、JournalLine、Payment、Allocation及command_receipts，不更新本金、费用、单据容量或账户余额。证据关联不产生新分录，关闭原财务期间不阻止有效证据关联。
- 复用已有绑定事务：咨询锁→全部排序账本→主体→实际涉及资产，然后锁OCR草稿与目标操作；该分支不产生资产分录，资产集合为空。新关联要求主体、原件和关联可用及付款操作active；往来/原资金账户后来归档不改历史付款身份。OCR计算在此前完成，不持有事务锁。
- 在ocr_confirmations增加可空payment_id，同账本FK引用business_payments；仅link_payment必须非空，旧create/link必须为空。新增分支验证Payment→原操作/凭证、所有者及永久Payment回执的一致性，OCR回执完整等于封存的原付款回执。保留原草稿/确认同时提交、版本/字段、原件/来源、有效关联及不可变历史校验；不修改财务历史/冲销链。
- 现有确认表已接changes，新增字段随原通知提交；已有重复来源查询同时覆盖三类确认。新迁移采用冻结SQL；存在link_payment历史时拒绝降级，允许降级时恢复0014冻结的确认校验和action约束并移除新增字段/FK。旧记录不补写或重算JSON/摘要。
- 新建原件直接关联付款时复用现有DocumentService及其操作ID，不通过legacy财务详情序列化Payment。OCR确认使用新分支，旧link不允许伪装为新付款回执。
- 网页沿用PendingConfirmationController的冻结所有者、账本、原正文、版本、稳定意图、防重复、401恢复、显式退出/异用户清理及迟到隔离。新回执核对目标付款身份、版本、原凭证及全部初始分摊成员；缺字段、乱序、错误目标或部分回执保持未知。新增成功后只重读当前记录，不由历史回执覆盖当前状态。

## 影响与拆包

先落本ADR；再拆内部契约/模型/迁移约束，事务服务/目标读取/HTTP与生成契约，双语网页及浏览器/完整bundle验收。中间存储包不开放未完整受约束的写接口；每包一个目标、约800有效行，同时最多一个迁移PR，四项CI与main复核后接续。

虚构B-05账单100、付款100及已分摊100，选择银行原件关联后经营费用100、银行实际扣款100、未结0均不变。验证同/跨账本原件、所有者隔离、旧六类OCR回执逐字保持、同意图重放/异体冲突/并发、版本/归档/取消边界、完整200行初始回执、每步回滚和直接SQL拒绝错误关联；关联前后所有财务表完全相同。备份恢复后原新/旧确认与付款回执重放均零写入。

网页覆盖中英、桌面/375/320、原件与候选对照、重复提交、丢响应/真实401、退出/迟到、失败路径和归档后历史读取。固定Tesseract人工确认方案不调优、不重跑正式OCR验收，样本全部明确虚构。

退款、贷项、整单更正取消、正式Invoice编号/PDF和代付属于后续依赖包；本决定不改变其金额或期间规则，也不实现T12客户端。

## 备选方案

把银行原件再次提交支出会双记资金和费用；仅按金额/日期猜匹配无法证明同一付款；修改旧operation回执会破坏原意图重放。另建不相交确认表会增加草稿终态互斥和重复提示的双重约束，当前复用同一封存确认表及明确分支即可保留原事务边界。
