# ADR 0030：经营草稿整单编辑与归档

- 状态：已采纳（技术细化）
- 日期：2026-10-09
- 依据：ADR0025、0028、0029和T06-2；不涉及确认后的财务语义。

## 背景

表头和行共同构成一个编辑意图，单行请求或自动换版本重试会导致并发覆盖及部分保存。

## 决定

- 完整保存必须传入父expected_version、完整可编辑表头和lines列表；缺少lines不能解释为清空。所有行稳定UUID保留，禁止跨单据或账本搬移；只允许draft状态。
- 沿用咨询锁→账本→主体→资产锁序，并在修改ORM对象前完成计价和引用校验，避免自动flush留下半套字段。所有修改和通知同事务提交。
- 校验父版本后每次成功保存父版本只加一；内容变动或归档/恢复的子行版本各加一，完全未变的行不触碰。旧序号保持，新行从历史最大序号后追加，删除操作归档原行；显式重新包含原ID可恢复该行。
- 同一引用ID默认保留旧快照；更换引用时生成新快照。refresh_snapshots=true才按当前资料显式刷新全部快照，不把资料更名当作用户已同意替换。
- 草稿归档/恢复使用独立的expected_version命令，只更新父归档状态及版本，保留所有行。归档草稿先显式恢复才可编辑；归档/恢复不要求当前引用仍可用于新输入，历史读取继续可用。
- 完整保存仍要求主体、资产及引用可用于新输入。类型或资产修改必须同时提供匹配的新行；最终状态仍受0023整单约束保护。
- 网络结果未知沿用ADR0025：冻结原请求及版本，读到更高版本只能进入待人工核对冲突，不宣称某次更新已成功；不得自动替换版本重试。

## 影响

本包只增加整单编辑及归档服务、schema和事务测试，不新增公开接口、迁移、财务操作或幂等回执。确认/结算仍由后续财务命令承担。

## 备选方案

逐行修改容易产生半张单据；删行会失去稳定身份；静默刷新快照会覆盖用户尚未核对的资料，因此采用父版本和完整原子保存。
