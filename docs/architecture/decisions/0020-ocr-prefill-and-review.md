# ADR 0020：OCR 建议值门槛与人工确认流程解耦

日期：2026-10-05。状态：已采纳；用户已确认本决定。

## 背景

ADR 0019 将候选质量门槛与 T05 的继续条件绑定。识别仅生成草稿，最终财务写入始终由用户明确确认；未达到建议值门槛也应能使用原文及候选开展人工复核。本决定取代 ADR 0019 的“双候选不达标即停止”与旧正式验收矩阵要求，其余隔离、文字层优先、许可及财务约束保留。

## 决定

- 清晰 OCR 关键字段门槛仍为 95%，清晰文字层仍为 100%；不把人工修改后的正确率计入引擎成绩。只有达到 OCR 门槛的引擎才可将解析为 certain 的 OCR 字段作为建议值预填，解析为 review 的字段仍待确认。
- 两候选同机同资源；只有一者达标就采用该引擎，均达标选精确率较高者，差距不超过2个百分点选 Tesseract。均不达标时仍接入 Tesseract，但所有 OCR 来源字段均待确认；保留候选值和原始证据，不把该路径称为达标。文字层来源按原解析规则预填；混合文档逐页区分来源，不能因含一页文字层而放行 OCR 页的字段。
- 网页同时显示原文、候选和需确认状态。用户逐项确认或编辑后才可提交；金额、日期、币种及方向、账户、分类使用既有财务规则。上传、识别、预填、编辑和复核均不产生分录。
- 旧正式输出只作只读诊断证据。改进只使用开发样本；使用新种子生成新的明确虚构正式样本，冻结真值、载体摘要、源码、模型、锁、配置、资源和顺序后才识别，不能根据正式输出调整再跑。
- 本轮只验收清晰文字层及清晰 OCR；热运行三轮、冷启动三次，保留质量、CER、稳定性与实际资源证据。退化和错误路径保持现有单测，不重复耗时实测；不删除困难清晰样本或忽略未正确字段。资源可在冻结前统一调整为4 CPU/8 GiB，或保留两者相同的既有预算。
- 一轮改进的新增修改代码约1500行内，生成语料、锁及证据JSON另计。重用现有基准工具；不引入新的基准平台。正式输入冻结后只运行一次；输入/安全/完整性失败仍是工程失败，质量未达标则输出复核策略并继续 T05。
- 不猜币种、不接受歧义日期、不做模糊纠错；跨列、重叠和不完整证据保留人工路径。OCR 计算无数据库锁；写入沿用咨询锁→账本→主体→资产及变更日志，最终确认复用 v2 幂等和原意图重放。

## 影响

worker 使用冻结的引擎身份与建议值策略，草稿记录字段来源及复核状态，网页按来源应用策略。策略变化不能覆写已有原始候选，也不能替代用户确认。正式质量失败不再阻塞 T05，临时复核路径的进度与限制只在 status.md 记录。模型、SDK、离线部署和人工确认的安全验收仍须完成。

## 备选方案

降低门槛、修改正式真值、推测缺失值或重复使用旧正式集均不采用。保留质量硬阻塞会阻止安全的人工确认流程，已由用户决定取消；人工兜底不能被用于宣称 OCR 达标。
