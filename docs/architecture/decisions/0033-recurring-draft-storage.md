# ADR 0033：周期草稿规则、实例与原子生成

- 状态：已采纳（技术细化）
- 日期：2026-10-09
- 依据：ADR0032、P-03/P-06、B-14；不依赖确认后的经营税额选择。

## 背景

稳定单据ID不能单独证明任务已提交。规则更新、生成后人工编辑、暂停和备份恢复都必须保持实例唯一性，不能重新解释已经生成的周期。

## 决定

- 规则和实例均归属账本，使用复合外键和同事务变更日志。规则有稳定ID、名称、版本、归档状态、显式IANA时区、原起点、周期单位/间隔、只读的下一个实例序号，以及从指定Invoice草稿版本捕获的输入快照。
- 捕获模板必须匹配同账本、未归档Invoice草稿的当前指定版本及完整输入投影（表头和按旧序号排序的有效行）。数据库冻结的投影校验复用既有草稿约束，不能在JSON内隐藏跨账本分类/项目。后续源草稿变化不自动改变已捕获模板。
- 起点、周期与时区不可改写；需要改变这些参数时显式停用旧规则并创建替代规则。名称和模板可携带expected_version修改，模板刷新必须重新指定当前源版本，历史实例不变。
- 归档停止新生成；恢复从第一个未生成实例继续，页面明确展示积压及恢复含义。需要跳过旧周期时使用新起点的替代规则，不暗中前移游标或删除实例。每次处理数量有上限，失败实例不被跳过。
- 实例以（规则ID、序号）唯一，并唯一绑定同账本单据；保存周期日期、使用的规则版本和原生成输入。实例追加后不可更新、归档或删除。生成的草稿仍可按普通草稿协议编辑或归档，任务重放只返回原绑定身份，不覆盖人工修改。
- 每个实例一个事务：咨询锁→账本→主体→排序资产，再验证规则/资料。先查询已提交实例以处理未知提交，成功实例不因当前资料归档而失去重放能力；新实例必须重验所有引用和计价，数据库核对生成输入与模板仅有ID和日期投影差异。草稿、实例、规则进度和通知一起提交。
- 规则的进度只能连续加一；延迟约束验证实例从0连续且数量与进度一致。插入实例时校验当前规则版本/待生成序号、周期日期、草稿原输入；插入并flush后再推进规则，避免半提交。后续读取或规则更新不重新拿已编辑草稿核对旧实例输入。
- 任务由jobs CLI调用，使用有时区的当前时刻换算规则当地日期，不推断服务器时区。时间库或引用不可用时报告稳定错误并保留进度。生成不入账、不分配正式编号、不发客户邮件。
- 降级拒绝删除任何规则、实例或其历史通知；恢复后同一实例只能返回原草稿身份。

## 影响

先落地模型、冻结SQL、范围/连续性/不可变约束和迁移测试；随后服务与任务、API、双语网页和B-14恢复验证。模板来自当前草稿快照而非自动跟随源记录；新规则和显式模板刷新须遵守资料可用性。

## 备选方案

仅靠任务完成标记可能与草稿分开提交；只查单据ID无法证明它由该周期生成；重试时重新复制可变模板会覆盖用户工作。采用原子实例记录和只前进的连续进度。
