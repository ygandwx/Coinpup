# ADR 0022：控制账户与维度的分包实施边界

- 日期：2026-10-09
- 状态：已采纳（技术细化，执行用户已确认的 ADR 0016 选项 A）。
- 关联：[ADR 0016](0016-account-classes-and-dimensions.md)、[优化计划](../../engineering/optimization-plan.md)。

## 背景

当前账户均为资金账户，T06 的往来单位、单据、单据行尚未建表。本轮仅实现账户及分录维度基础、约束和往来余额查询，不提前实现经营单据或结算命令。维度不能使用无外键的任意 UUID 占位。

## 决定

1. 首包新增 `account_class` 和账本内唯一的 `system_key`；旧行默认 money，原支付 kind 保持不变，系统账户 kind 为空。类别与系统身份创建后不可改；通用账户维护、五类财务命令及原余额入口只接受 money，旧请求/响应与永久回执保持不变。
2. 控制键固定为 `receivable.customer`、`payable.supplier`、`intercompany.receivable`、`intercompany.payable`、`advance.received`、`advance.paid`，分别对应应收、应付、应收往来、应付往来、客户预收、供应商预付。各方向独立，数据库校验 key 与 class 配对，不因同一资产或对手方抵销。
3. 后续维度包只建立往来单位、单据及单据行的最小引用身份模型和复合外键；不增加创建它们的公开接口、Invoice 状态机、结算或业务金额字段。T06 在这些身份上扩展业务资料与命令。新增业务表接入同事务变更日志；跨主体维度通过账本所有者与主体所有者的复合外键隔离。
4. 历史分录维度保留空值；新增维度随封存行不可变，冲销逐字段复制并精确反号。保留现有历史校验和形状分发链，在其上追加维度检查。禁止通过补写历史行或放宽归属约束迁移。
5. 最后补同事务内部控制账户/资产获取入口，按咨询锁→账本→主体→排序资产处理，停用/归档不自动恢复。往来余额由独立只读入口按账户、资产及完整维度组合汇总，保持有符号原币数量；本轮不实现 T06 写命令或 OPT-24 跨账本结算。

## 影响

顺序小 PR：账户类别与旧入口隔离 → 引用模型/维度/冲销约束 → 系统账户与资产自动管理/往来余额查询及恢复验证。每次显式冻结迁移、单 head；存在新增账户身份、维度或其历史时拒绝丢失语义的降级。旧 `*_constraints` 用例不修改；测试夹具中当前迁移 head、显式清理与触发器登记按新增模型维护，仍使用 RESTRICT。

## 备选方案

延后所有维度到 T06 会留下本轮已授权范围未完成；任意 UUID 或去掉外键会削弱归属不变量。采用最小引用身份，完整业务功能仍留 T06。
