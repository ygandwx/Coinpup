# ADR 0004：独立账本、结构归属与修改版本

- 日期：2026-10-03。
- 状态：T02-2 / T03 基础结构接口实施，实际验证见[状态](../../engineering/status.md)。
- 承接：[精确金额与资产身份](0003-exact-asset-amounts.md)。

## 模型

首版只有一个管理员，使用管理员 ID 作为工作空间的访问所有者，不先引入公共注册或协作工作空间。每个个人/公司主体创建一个独立主账本；公司可以有多个，不能通过全局默认公司省略归属。

迁移 `20261003_0003` 增加 `assets`、`entities`、`ledgers`、`accounts`、`account_assets`、`categories`。账本按主体唯一，账户支持多种资产；本次没有余额列或记账分录。金额基础继续由 ADR 0003 定义。

服务按会话所有者查询主体和账本。数据库复合外键进一步约束账本所有者、账户资产的账本以及分类父节点的账本和收支类型。不同账本允许同名账户/分类，不按名称合并。

## 身份与配置

- 资产目录迁移内置五种法币和 BTC/ETH/XMR。其他原币、USDT/USDC 使用显式精度和必要的网络/代币配置；配置不进行链上操作。
- 资产身份和精度永久不可原地修改；可停用，历史引用仍保留。需要纠正错误资产时新建正确配置，再通过明确业务流程迁移引用。
- 主体类型/所有者、账本所属主体/所有者/基准币、账户所属账本及分类所属账本/类型/父节点不可直接改写。报表展示币种不是账本基准币。
- 此增量支持创建子分类、改名与归档；暂不提供分类移动。父分类必须先存在，再创建子分类，数据库拒绝单行及批量创建循环。
- 公司资料只按已确认的地区/类型做输入一致性检查：CN 有限责任、HK 私人有限、US NM/WY LLC、EE 私人有限。法律编号说明、证件、法定期限和地区表单在相关功能实现时核验；本次不自动推断法律义务。

## 模板、归档和修改

个人/公司常用分类模板保存在不可变的程序配置中。创建主体时可以选择一个模板，事务内复制为独立 UUID 分类；保存原始模板来源键以便追溯，后续模板或某个主体的分类更改不传播到其他账本。语言选择只影响复制时的初始名称，后续切换界面语言不自动翻译原始业务名称。

所有更新必须提交 `expected_version`。服务锁定目标并核对版本，成功时加一；旧版本返回 409，不静默覆盖。账本内写操作统一按账本、主体、所需资产的顺序获取锁，主体归档与账户/分类新增不会同时穿过检查。

归档保留记录和引用。主体归档后可以读取历史，但暂停其账本写入，恢复后继续使用；分类有有效子项时不能直接归档父项。账户移除一个支持资产时把关联停用，不删除关联行。版本不是完整同步或审计服务；后续入账修改需要独立的不可变历史和业务操作版本。

## HTTP 合同

`/api/v1/entities`、`/assets`、`/category-templates` 和 `/ledgers/{id}` 下的账户/分类接口复用管理员会话。写入同时检查精确 Origin 和 `X-CSRF-Token`。请求不能指定访问所有者，服务始终使用已验证会话中的 ID。

实体、账本、账户、分类接受客户端生成的 UUID，以便后续 App 复用；重复 ID 返回冲突，不覆盖已有数据。本增量尚未实现财务请求的幂等重放。列表使用稳定 ID 排序、`limit`（1–200，默认 100）和有界 `offset`；这不是离线增量同步游标。

参数有类型、长度、额外字段和资料字段数量限制。输入错误不回显原始值，领域错误给出稳定 code，数据库异常不泄露 SQL 或连接信息。当前接口提供结构管理，不能创建收支或查询余额。

## 恢复与验收

备份验收通过实际服务创建虚构个人/公司、多资产账户、复制分类和归档记录，比较恢复前后所有应用表的精确文本及关联。还要通过恢复后的服务读取结构，而不只检查备份命令退出状态。文件附件尚未实现，不声称覆盖附件。

T02-2 验证 A-01/A-02/A-03 的结构部分：主体隔离、模板复制、账户支持多资产。地区页面/证件、余额及完整手工记账闭环仍待后续增量。真实数据库迁移往返、触发器、并发版本、HTTP 会话和恢复结果必须有 CI 证据后才集成。
