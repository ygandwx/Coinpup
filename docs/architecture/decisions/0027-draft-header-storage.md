# ADR 0027：草稿表头与旧单据身份隔离

- 日期：2026-10-09
- 状态：已采纳（ADR0026草稿存储的技术细化）。
- 关联：[ADR0022](0022-control-account-implementation.md)、[ADR0026](0026-draft-pricing.md)。

## 背景

business_documents已被不可变分录引用。给这些旧身份补造可编辑业务内容会改变历史含义；草稿也不能被原财务命令当成有效单据。表头和行分包迁移，仍须在每一步保护这些边界。

## 决定

1. 在原表追加可空document_kind、state、party_id、asset_id、issue_date、due_date、notes、issuer_snapshot及party_snapshot。旧行全部保持SQL NULL，不回填；完整新行只能是invoice/bill方向的draft，必须具备往来、资产、日期和两个JSON对象快照，不允许半配置行。
2. 往来使用(id, ledger_id)复合外键，资产使用现有完整asset_id外键，全部RESTRICT。日期只保存明确日历日期；到期日可以为空或已过去，不凭注册地推算条件。快照保存已选主体/往来的显示资料，后续服务从鉴权作用域内资料构建，不接受客户端任意快照冒充归属。
3. 原UUID、账本、创建时间、版本递增和禁止删除规则继续生效。旧匿名身份与新草稿是不可互换的模式；即使旧身份暂未被引用，也不能转成草稿。草稿编辑/归档继续expected_version，不允许抹除业务内容回退成匿名引用；后续确认状态转换单独冻结迁移。
4. journal_lines新增INSERT保护：只要document_id指向draft，即拒绝写入。原匿名引用保持原校验链和语义；既有行封存、历史、冲销、期间锁及永久回执均不变。先插分录再把匿名身份改成草稿同样被身份保护拒绝。
5. 沿用business_documents的同事务变更日志，不新增通知类型。写服务仍遵守咨询锁→账本→主体→资产顺序；此包只有模型，不开放绕过该服务边界的HTTP接口。
6. 迁移只追加字段、约束及两个专用保护函数；降级先拒绝任何完整草稿（包括已归档），无草稿时恢复0016原身份触发器并移除新保护。旧匿名行、原通知与财务事实必须逐值不变。

## 影响

表头先落地，分类/项目行、精确计价存储和父版本一致性随后单独实施；在它们完成前不提供草稿公共接口，不把表头当作完整业务能力。中英文虚构快照加入完整bundle恢复，验证归属、原值、版本及既有回执重放；所有原约束测试保留。
税额计价依ADR0026已确定；确认单据后的经营统计是否含税是独立产品口径，不在表头包隐含决定，也不阻塞保存草稿所需的数据设计。

## 备选方案

独立新表重建单据身份会割裂既有引用；把旧匿名身份直接升级成可编辑草稿会改变历史事实。仅在应用层阻止草稿入账不足以保护数据库，采用独立INSERT约束及不可互换身份模式。
