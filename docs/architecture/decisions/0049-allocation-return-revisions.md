# ADR 0049：分摊退回整组更正与取消

- 状态：提议（技术细化）。
- 依据：P-03、B-11 及 ADR 0008、0014、0015、0017、0040、0043、0044、0047、0048。

## 背景

分摊退回释放原付款和原单据的已应用额度。更正或取消较早的退回可能影响后续分摊、贷项、退款和同一来源的末笔舍入。原分摊、每次退回、已发行的回执及明确的证据引用都须保留。

## 决定

- 固定原退回组、账本、付款及往来。更正提交预期组版本、修订原因、生效日期、业务说明和 1–200 条完整有序的替代事实。每条绑定互异的原应用行、来源版本、付款侧与单据侧的精确数量。原应用必须符合 0043 的 active/v1 条件。取消提交预期组版本和原因。
- 保留的来源沿用原成员操作，完整冲销后写替代。移除的来源完整冲销并终止。新增或移除后重新加入的来源取得新的 v1 操作。取消冲销所有当前成员并终止该组。从实际封存分录复制原日期、金额、组件、角色和维度，按资产配平。退回修订自身只改变往来重分类。
- 替代日不得早于所用的原应用日期。旧冲销和新替代各自的交易日与归属日均须开放。停用的旧引用可用于精确冲销。主体归档阻止新写入，历史回执仍可重放。
- 先获取写事务咨询锁，再按账本、主体和排序后的新旧资产加锁。按锁后的新快照一次模拟整个目标组的替换，扣除其旧贡献后加入替代事实。组头、全部成员、凭证、操作头、永久回执及同步通知同事务写入。数据库拒绝跨账本来源、孤立推进、残缺成员、缺回执和终态复活。
- 每个原应用行在两个资产侧的有效退回数量均不得超过原量。付款侧以有效分摊减有效退回得到净应用 A，须满足 A ≥ 0 且 P − A − R ≥ 0。P 为原付款本金，R 为所有当前有效退款本金。单据行以其自身资产计算净应用，须非负且加有效贷项含税额后不超过原含税额。贷项净额和税额各自的累计上限继续生效。
- 按 0043 的整数最小单位算法证明原比例和末笔差额。部分退回正数半入，全退吸收付款侧剩余。单边残余、零付款单位或任一侧超额均拒绝。来源序列按可证明的写入顺序追加，保存前驱、当时两侧前缀和末笔条件。已取消的来源序位永久保留，回填日期不会重排历史。
- 更正一笔较早的退回时，须验证后续已保存的同源金额仍符合上述规则。例如原付款侧为 5、单据侧为 4 个最小单位，先退 3/2，末笔退 2/2。取消首笔将使后笔成为部分退回，其应为 3/2。数据库须拒绝该取消，即使当前净量仍在上限内。
- 按 0044 的有序 ID 明确关联退回。退款保存当时实际引用的退回组版本，旧记录绑定不可变原版 v1。一次退回可被多个有效退款引用。更正退回时须保留有效引用的身份并核验替代日期不晚于各退款日期。**只要任一有效退款仍引用该退回，取消一律拒绝。** 操作者须先显式更正退款的当前证据，随后重新提交取消。并发时在写锁内重读全部有效引用和容量。旧证据、原件及各版回执永久保留。
- 账本内 v2 幂等摘要绑定动作、组 ID 与收到的原 JSON。授权后先核对原键并返回固定历史回执。新 200 保存修订 ID、组版本、原/替代事实与有序成员的旧凭证、冲销及可空替代凭证。原付款、分摊、退回、退款和贷项各自的 201 沿用原响应。
- 持久化层从完整版本投影有效退回及对应证据。Python 和数据库的分摊、退回、退款及贷项容量使用同一有效事实，按候选源集合批量读取。完整组、连续版本、指定历史回执及操作头均可证明后开放写入。存在修订事实或其通知历史时拒绝降级。

## 影响

虚构案例中付款 100、应用并全退 20、有效退款 5 引用这次退回。即使取消后可用本金为 75，仍须因有效引用拒绝且零写入。显式更正退款证据后，取消仍须通过期间、比例、后续末笔和容量检查。

验收涵盖双向、同跨资产、部分退回、重新加入、三类容量竞争、同键和同版本并发、跨账本、停用旧引用及中途失败后的整组回滚。双语网页须恢复原命令与回执。空目标恢复后核对旧/新事实、证据版本、来源顺序、全部回执、私有原件及通知。逐一重放成功回执后每张业务表和变更日志均应相同。

## 备选方案

覆写历史会改变旧证据和回执。自动解除退款关联、级联修改后续退回或重分摊会改变操作者未提交的意图。仅核验当前净量无法识别旧的末笔舍入错误。完整组替代使冲销映射、来源顺序和各版回执均可独立验证。
