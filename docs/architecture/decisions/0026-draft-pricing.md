# ADR 0026：经营草稿与逐行未税计价

- 日期：2026-10-09
- 状态：已采纳（用户确认Invoice计价方案A；草稿边界为技术细化）。
- 关联：[需求P-03/P-06](../../product/requirements.md)、[验收B-13](../../product/acceptance.md)、[ADR0024](0024-business-master-data.md)。

## 背景

T06已有往来、项目及单据引用身份，但没有业务内容。Invoice采用未税单价→行折扣→手工税率、逐行按币种精度四舍五入后合计。必须把可编辑草稿与产生不可变财务事实的确认分开；不得把付款与单据重复计费。

## 决定

1. 草稿沿用business_documents及business_document_lines的同账本身份。旧匿名身份保持无业务内容，不伪造历史。销售Invoice与供应商账单各有方向；一期每张单据一个完整资产身份，每行有描述、数量、单价、折扣、税率、分类、可选项目和业务归属日。
2. 数量和税率均为非负ASCII十进制字符串，不接受JSON数字、指数、符号、空白或Unicode数字；数量必须大于零。沿用NUMERIC(38,18)的最多20整数位、18小数位作为存储/输入上界，不依赖Decimal上下文。税率单位为百分比，0表示不加税，不限制在100以内、不推断税务适用性。
3. 单价和行折扣是单据资产的非负精确金额；折扣以固定金额表达，默认0，不能超过数量乘单价的精确值。首版无整单折扣或百分比折扣字段，界面明确标注折扣金额；不自动分配隐含折扣。零单价和全额折扣允许保存草稿；正式确认要求单据合计为正。
4. 以整数/有理数计算：每行未税额N=round_half_up(数量×单价−折扣)，税额T=round_half_up(N×税率/100)，行合计G=N+T。两次舍入都按该资产最小单位执行；单据各项合计分别累加已舍入的行值，不对整单重新计税。任何行、中间持久化金额或累计金额越过Amount上界则整次计算失败，不钳制、不截断。
5. 同一纯计算模块用于草稿保存、读取核对、以后确认及PDF数据；不接受客户端声称的净额/税额/合计作为事实。草稿最多200行；空行集可作为编辑中草稿返回零合计。所有输入拼写由后续请求保存，金额输出沿用固定资产精度；本模块无数据库、网络、分录或回执副作用。
6. 草稿写入采用稳定UUID、expected_version及咨询锁→账本→主体→资产顺序。整张草稿与行原子保存，行身份不换账本/父单据；移除行归档而非删除。行修改也提升父单据版本，所有业务变化同事务进入现有变更日志。客户端原意图与冲突处理沿用ADR0025。
7. 保存草稿时持久化展示所需的主体、往来及分类/项目资料快照；资料后来改名不静默重写已保存内容。编辑时可显式刷新快照，返回新版本给用户复核；确认使用已审阅的草稿版本与快照，不在提交时暗换展示资料。引用仍使用复合外键，快照不能代替身份归属校验。
8. 草稿不产生分录、应收应付或资金变化，不因保存而占用Invoice正式编号。已有财务引用的旧身份不可变成可编辑草稿；确认后内容与快照不可变，更正/取消另走追加历史及永久v2回执。具体确认命令和凭证形状先新增技术ADR，继续保持期间锁与原五类命令合同。

## 影响

按依赖交付纯计价→草稿模型/约束及迁移→服务/API→中英网页与恢复；每包保留旧API和旧回执。模型迁移验证旧NULL兼容、同账本引用、版本、不可变历史及拒绝丢失数据的降级；服务验证整笔回滚、通知、未知结果；界面验证中英桌面/手机、重复与中断。
计价必须覆盖半个最小单位、逐行/整单舍入差异、不同资产精度、折扣边界、零值、最大值/溢出、无效输入及恶意Decimal上下文。草稿和确认后的财务统计分开验收，不把计算器视为完整T06。

## 备选方案

含税/未税双模式与手填行总额未被采用。浮点、整单二次舍入、地区默认税率和隐式折扣分摊会改变已确认规则；独立再建一套单据身份则割裂现有分录外键。
