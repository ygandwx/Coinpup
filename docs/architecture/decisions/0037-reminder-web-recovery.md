# ADR 0037：提醒事项网页的原意图恢复

- 状态：已采纳（技术细化）
- 日期：2026-10-10
- 依据：ADR0025、0034、0036；不增加财务命令或产品范围。

## 背景

事项编辑、重算、人工日期和完成状态分别推进版本。响应丢失后，即使当前字段或历史修订相同，也不能证明本次请求已成功；规则升级和主体资料变更也不能自动替代用户选定的计算依据。

## 决定

- 提交时冻结所有者、账本、事项UUID、动作和完整JSON正文。保留原expected_version与规则ID/版本；重试原正文并使用当前会话CSRF，不读取当前表单重新组成请求。
- 创建使用稳定UUID。未知创建遇到重复ID时读取同账本同ID；只有版本1、未完成/未归档、标题/说明、人工日期/理由及原请求规则ID/版本/参数完全匹配才确认。后续任何变更都按冲突处理，不自动覆盖。
- 更新的直接成功响应须符合事项归属、操作者、下一版本、动作和对应请求字段。未知结果读取到更高版本只证明存在变化，仍显式显示冲突；历史用于人工核对，不充当永久财务回执。读取失败保留未知状态，不递增版本或生成新ID。
- 提交中及未知状态阻止新意图与账本切换。401隐藏私人内容，原所有者重新登录后手动恢复；用户切换/主动退出清除意图，忽略迟到响应。正文只存页面内存，不写本地存储或日志。
- 展示当前计算值、人工覆盖、有效日期、完成/归档和计算状态。规则目录由后端提供来源/版本/核验日期；缺资料、待核验及不适用分开显示。重新计算是明确动作，不能因打开页面或规则目录更新自动执行。
- 人工覆盖设置/清除均要求理由；完成与投递状态分开。修订按版本分页展示依据和用户动作，只读，不提供历史编辑或硬删除。

## 影响

先交付API封装、响应核对与原意图控制器，再接中英页面和1440/375/320浏览器验收。覆盖双击、响应丢失、401、原意图重试、并发版本变化、读取失败、用户切换和迟到响应；仍须真实数据库与恢复证据。

## 备选方案

将最新字段相同视为成功会混淆并发修改；自动改用最新版本会覆盖其他决定。采用已验证的非财务原意图模式，独立保留提醒计算依据和历史。
