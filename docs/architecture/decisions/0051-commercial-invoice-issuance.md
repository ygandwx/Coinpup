# ADR 0051：商业 Invoice 正式编号与双语原件

状态：提议（T06-6 技术细化）。依据：C-10、P-06、B-13、ADR 0012、0014、0015、0026、0032 与 0050。

## 背景

业务确认和修订已经确定应收与计价事实。商业 Invoice 的号码、公司展示资料和中英文 PDF 是另一组需永久保存的发行证据。下载时重新排版旧单据，或从变化后的公司资料生成原文件，会改变已经交付的内容；把号码分配给周期草稿又会把待审核草稿误当正式发行。

## 决定

- 正式发行仅接受授权公司账本的当前有效 Invoice，绑定预期单据版本和预期公司发行配置版本。供应商账单、个人账本、未确认或已取消单据不能新发行。发行不确认草稿，不新增资金、应计、贷项、税额或分录；周期任务仍只生成草稿。
- 公司发行配置有稳定身份与连续版本，包含编号前缀、最少数字位数、Logo 私有原件引用、展示资料和收款说明。前缀与位数由用户配置；数字部分从 1 开始单调递增，不自动按日期重置。位数是补零下限，不截断超宽序号。不允许用户回拨已使用序号。配置归档不删除发行记录。
- 序号以精确整数计算、十进制字符串传输。每家公司有独立序列和完整号码唯一约束；修改前缀、位数、语言、模板或配置版本均不复用旧号码。历史唯一性跨配置版本维持；配置变更若导致候选号码与旧号码冲突，明确拒绝并要求调整配置，不静默跳过一批号码。
- 一次发行有稳定客户端意图 UUID、账本作用域幂等键和 v2 原 JSON 摘要。授权检查后优先匹配已有意图及摘要；同键不同正文或同意图不同键冲突。成功回执永久重放，之后的资料归档、单据修订、配置变化和期间关闭不能改变旧结果。
- 新意图在短事务中先取得咨询锁、账本、主体与公司序列锁，核对当前版本、有效状态和资料归属；原子保存号码预留、发行快照、原请求摘要与通知，推进序列。一份单据的同一有效版本只允许一个发行意图；竞争的新键返回明确冲突，不把其他意图的结果当作本次成功。
- 预留是持久的待完成记录，已分配号码永久不回收。渲染失败不生成成功回执，同一意图重试继续该号码及快照。号码可能因未完成意图出现空缺，界面和历史明确展示，不声称具备任何地区法定税务发票的连续编号能力。
- 快照保存该版完整 1–200 行，包括零行、精确输入、已确认净额/税额/含税额、折扣和手工税率、资产身份与精度、开票日、到期日、客户与发行人资料。发行配置的额外展示资料、收款说明和 Logo 字节身份另行冻结。以服务端已验证版本事实为依据，不重新从当前资料拼出历史，不重新计算或改写单据计价。
- 一次发行同时准备中文与英文 PDF，使用同一号码、同一事实和固定模板/字体版本。界面标签可翻译，用户填写的名称、地址和说明保持原文。字体必须覆盖虚构验收的中英文并嵌入文件；输出换行和分页覆盖长名称、精确金额、200 行与页脚，不能截断末行。模板不执行用户 HTML，不获取远程 Logo、字体或图片。
- 渲染在数据库事务外进行，限制时间、内存、页数和输出大小；使用服务端锁定的本地依赖及私有临时目录。Logo 先经过有界解码，字节身份固定；不把任意上传文件作为可执行模板。两个 PDF 均持久写入并完成摘要、大小和 fsync 核对后，才可封存最终元数据与回执。采用现有 FileStore 的私有文件约定；不引入公共静态文件目录。
- 结束事务重新取得相同作用域锁并核对预留与渲染输入身份。并发完成只能封存一组规范文件，另一组未引用 blob 按现有孤立原件边界保留。文件元数据、同账本发行关联、两种语言、固定回执和通知必须同事务提交；只有一份 PDF 就绪不构成成功。
- 预留阶段已确定被授权发行的确切版本；之后单据或配置变化，不把旧意图改绑到新内容。恢复该意图仍完成原版证据，当前界面同时明确该版本是否已被更正或取消。新发行另行审阅当前版本，以新意图和新号码关联前次发行；旧号码、两份原文件及全部链路保留。
- 待完成响应明确为 pending，与最终封存回执区分；它不是财务成功回执。客户端冻结原意图、键、正文和所有者，未知结果原样重试；只在完整校验原意图的两份文件身份和固定结果后显示完成。不因当前单据、号码列表或单份 PDF 存在就自行认定完成。401、主动退出和迟到响应沿用现有控制器边界。
- 列表、固定详情及下载检查账本归属、会话与 no-store；下载提供原始存储字节并复核摘要，不现场重新生成旧文件。发行与前驱的复合键拒绝跨账本、跨单据串用，最终事实与回执不可改写，历史不能被硬删或保护性降级丢弃。
- 完整 bundle 同一快照保存发行配置、序列、待完成意图、固定回执、发行链、Logo 及两份 PDF 元数据和字节。空目标恢复后旧回执重放零写入；待完成意图可用原键继续，后续新号码不重复。不使用真实客户资料，不发送客户邮件。

## 影响

按编号与快照纯契约、封闭存储、受限渲染、事务/API、恢复和双语网页拆包；每个迁移独立审查，完整约束及原件保障齐备后才开放正式写入口。验收覆盖两个虚构公司相同前缀独立编号、同键并发、未知提交、单份渲染失败、封存失败回滚、同版本竞争、配置变化、版本更正后新号和旧双语文件不变、账本隔离及完整空目标恢复。仅设计或仅 PDF 可生成都不等于 B-13 完成。

## 备选方案

下载时动态生成无法保证旧字节不变；在长数据库事务内渲染与写文件会长期持锁；先返回成功再异步补 PDF 会产生缺失原件的成功发行。永久预留及原意图恢复将中断显式表示为待完成，并保持号码与事实绑定。
