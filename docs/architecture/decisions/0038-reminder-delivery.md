# ADR 0038：提醒计划与双渠道投递结果

- 状态：已采纳（技术细化）
- 日期：2026-10-10
- 依据：P-07、C-09/C-10、ADR0035/0036；不产生财务分录。

## 背景

事项日期和完成历史已具备，尚未启用站内或邮件投递。数据库唯一键能保护发送身份，但不能证明断线之前外部邮件服务器是否已经接受，不能将未知结果当普通失败反复发送。

## 决定

- 每事项一个显式配置：提前天数、IANA时区、当地分钟、站内/邮件渠道、收件邮箱和中英语言。不采用主机默认时区、不猜法定日期；没有有效日期、事项完成/归档或主体归档时阻止新投递。生产SMTP配置在部署环境提供，凭据不进入业务表、API、日志或证据。
- 时间内核只接收明确日期与参数。提前量为0至3660天，当地时间为0至1439分钟；超范围拒绝而不截断。使用标准库zoneinfo从已锁定的第一方tzdata包加载，记录数据版本；拒绝主机localtime及特殊目录/路径穿越。重复当地时间选择较早UTC，缺失分钟顺延到同一当地日其后首个有效分钟；整日不可用或越界明确阻塞。返回实际采用时点用于解释，截止日本身不改动。
- 保存计划UTC、有效日期、请求/实际当地时点、tzdata版本和计算输入快照。输入未变化时复用已保存UTC，不能因tzdata升级或编辑标题静默重排。仅到达时点才创建投递；过去的显式计划在下一次任务运行时处理一次，不补造循环通知。
- 配置采用版本条件更新和追加修订。任务分批遍历启用配置，不能仅筛选旧计划已到期者：有效日期可能被用户改早。领取前核对当前事项/主体并刷新改变的计划；GET只读，展示保存计划与是否待刷新。
- 投递以事项、渠道、计划UTC为永久唯一身份。改变邮箱但保留此身份，不会重发成功或未知通知；再次通知须显式设定新时点。成功、未知、取消与旧尝试历史保留，完整恢复后仍受唯一键保护。
- 当前投递与追加版本快照保存每次尝试的编号、冻结内容/事项版本/日期依据/收件人、稳定Message-ID、状态和时间。只有从未发送或明确未被接受的失败允许在下次领取前按最新显式配置重新规划并追加记录；发送中、未知、成功尝试的原证据不可改写。
- 领取遵守咨询锁→账本→主体并在短事务内提交。SMTP连接、认证与传输不持业务锁；结果另起短事务凭租约令牌确认，迟到worker不得覆写新状态。租约过期保守标为未知，不能推断未发送。编辑/完成/归档阻止尚未开始的发送，但已开始的SMTP可能完成，界面不承诺外部原子撤回。
- 站内内容与成功状态在同一数据库事务保存，阅读状态、事项完成与邮件状态彼此独立。邮件“服务器已接受”不等于已读或最终送达。
- SMTP连接/认证阶段尚未进入发送的失败、明确否定且未接受邮件的回复可按临时/永久原因处理，暂时失败采用有界退避；永久失败或耗尽保留可见状态供显式重试。进入发送后的断线/超时而无明确否定回复一律未知，不自动重发。服务器接受后QUIT/close失败不覆写已接受结果。
- 未知只允许带理由记为“已核实收到”或“停止本次通知”；不能直接重试同一未知身份。新时点可形成新的明确意图，旧未知证据仍保留。恢复命令保留原正文/版本，不因当前字段相同就自动判定原命令成功。
- 邮件使用单个明确地址与纯文本UTF-8正文，防止头部换行注入；生产仅支持校验证书的STARTTLS/SSL，不新增关闭证书验证选项。缺少配置明确阻止邮件，站内渠道独立。开发只使用虚构数据、显式测试时钟和隔离假SMTP，不连接真实邮箱。
- 所有新增业务表接入变更日志，归属使用账本/事项复合约束，禁止删除历史；不借用或削弱财务永久幂等回执、逐资产配平及期间锁。
- 备份只能保存当时的数据库事实，不能证明恢复点之后的外部邮件未发送。恢复在隔离目标执行并保持出站任务暂停；核对恢复点后的发送记录后才明确恢复调度，无法核实的既有任务按未知处理。不能根据旧备份中的pending状态自动补发；恢复检查同时覆盖备份内成功不重发和恢复点后未知保持暂停。

## 影响

按依赖拆包：时间协议与内核 → 配置/修订模型迁移 → 投递/尝试历史迁移 → 配置服务/API → 双渠道任务与恢复 → 中英网页及C-09验收。每个迁移包单一head、约束负例和完整bundle恢复；同一时间只开放一个迁移PR。

C-09使用三类虚构事项提前7天触发站内和隔离测试邮箱。覆盖并发唯一身份、明确失败重试、接受后丢响应/租约超时、迟到确认、配置/日期变更、完成归档、跨账本拒绝、恢复不重发与中英桌面/手机失败路径。真实SMTP、服务器与调度启用留到部署授权。

技术依据：[Python 3.12 zoneinfo](https://docs.python.org/3.12/library/zoneinfo.html)、[smtplib](https://docs.python.org/3.12/library/smtplib.html)（2026-10-10核对）。库能力来自文档；重复/缺失时刻及未知结果处理是本项目的保守技术选择。

## 备选方案

以每次发送前的当前tzdata重算会改变已确定的发送身份。把全部异常当失败重试可能重复发送已接受的邮件；单靠Message-ID也不能保证外部恰好一次。采用稳定身份、租约与未知状态，不另引入Redis/Celery或自动客户Invoice邮件。
