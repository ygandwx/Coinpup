# ADR 0044：真实退款与原付款本金容量

- 状态：已采纳（用户已确认独立退款口径的技术细化）
- 日期：2026-10-15
- 依据：P-03、B-11、ADR0008/0014/0040/0043；退款与贷项分别记录的用户决定。

## 背景

分摊退回释放已应用本金，不代表资金已经收回或付出。用普通收入/费用记退款会重复改变经营收支；直接修改原Payment会丢失银行证据与永久回执。真实退款必须保留原付款及明确的实际资金数量。

## 决定

- 新增独立BusinessRefund不可变事实，必填原payment_id、原付款expected_version、客户端UUID、实际交易日、原因、实际资金账户/资产/正数量，以及本次退还的原付款资产本金payment_amount。方向由原付款推导：客户收款的退款是资金支出，供应商付款的退款是资金收入，不让调用者另选相反方向。
- 原付款、往来与全部来源必须同账本，当前原付款操作须有效。只引用原付款或显式分摊退回，不自动匹配同名往来、单据或原件；归档历史仍可查询，原意图重放先于当前可用性。
- 同资产时实际数量与原付款本金相等；跨资产时两种数量由用户明确填写，使用原付款资产控制行与实际资金资产行，各自通过exchange角色配平。不得用报价或分摊比例冒充真实退款汇率，不推定汇兑损益。
- 原receipt的退款：资金减少、advance.received增加；原payout的退款：资金增加、advance.paid减少。本金不新增income/expense行。可选手续费复用现有显式FeeCreate及独立费用行，不自动退还旧手续费，不把净到账金额当作退款本金。
- 可退本金为原付款本金减累计有效退款本金及净已应用本金；每笔及累计均不能超限。已有应用必须先明确退回才能退款，不隐式猜测源行。独立成功的退回与随后真实退款是两个业务事实，界面明确分步，不能把两个HTTP请求标为一次原子操作；退款失败不抹去先前真实保存的退回。若未来提供同次意图的组合入口，必须另行在同一事务中协调，不能客户端自动串接。
- 可选allocation_return_ids保留明确原因关联：去重、同付款/账本、已经完整保存，不因关联而再次释放容量，也不把关联ID本身当作数量。一个退回可以分次退款，累计本金约束阻止重复支取。无既往分摊的预收/预付可以直接退款。
- 退款交易日明确填写，不早于原付款日及显式关联退回日，并处于开放期间；记录时间另存。退款与贷项可不同日，独立回执与原始事实永久保留，不伪装成原日期冲销。原单据/付款期间关闭不阻止在开放期间新增退款。
- 新POST `/business-refunds`使用独立命令kind、路由绑定v2原JSON摘要及永久账本键；响应完整保存退款ID、原付款、两侧本金、操作/凭证及费用映射。未知提交只重试原键/原正文，原回执复核不可变来源，不依赖当前可退量、归档或期间状态。旧付款/分摊/OCR证据回执逐字不改。
- 咨询锁→账本→主体→所有本金及费用资产一次排序加锁，READ COMMITTED锁后读取净容量；检查最终余额、精度、角色及来源，全部本金/费用/退款记录/回执/changes同事务提交。并发退款与新分摊共用锁及同一容量定义。
- 新表接入同账本复合外键、不可变/封存及changes保护；独立refund形状和累计本金延迟约束，不改旧五类/付款/分摊的形状及历史冲销链。有退款历史时拒绝降级；空历史降级恢复冻结原容量SQL。原constraints测试保留。
- 旧Payment读响应形状与原amount不变：applied_amount仍是净应用量，unapplied_amount扣除已退款本金，避免退款后的钱再次分配。无退款时JSON与改动前完全一致。新增只读退款列表/详情/当前容量提供累计退款、原因关联及完整原回执，不能把当前量当作旧提交成功证明。
- 贷项另按用户手填净额/税额冲减原分类，不由退款自动生成；未收到退款的贷项可以留往来。整单更正/取消仍按ADR0008完整冲销和版本链，不能用真实退款替代错误记录的历史修订。

## 影响与验证

按契约/纯计划、冻结存储与约束、原子服务及容量、API、双语页面/原意图、bundle拆包。网页明确展示原本金与实际资产两种数量、分步退回及当前状态；两语言三宽度检查重复点击、丢响应、401/换用户、迟到、范围/关闭期间/容量失败。

覆盖客户/供应商、同币/跨币、无分摊及先退回、独立费用、精度极值、逐资产守恒且本金不改费用、同键/竞争容量、任一步回滚、旧证据/回执不变、归档/停用后重放。空目标完整bundle恢复后重放所有原请求，比较全部表与私有文件；无退款的旧API响应保持不变。

B-11同步澄清为用户已确认的独立事实：费用100，先明确退回20、贷项20、真实退款20后，费用和净资金流出各80；只有退款时费用仍100，只有贷项时资金流出仍100。不能用原先把退款自动当费用减少的表述覆盖已确认规则。

## 备选方案

普通收支会重复确认费用；负数Payment破坏旧正金额合同；自动按剩余余额猜源行丢失明确意图；重写旧回执使中断恢复不再可靠。独立退款及严格净本金容量保留可审计来源，不扩展库存、税务申报或银行自动对账。
