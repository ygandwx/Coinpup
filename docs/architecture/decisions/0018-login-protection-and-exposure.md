# ADR 0018：来源登录防护、可选 TOTP 与私网访问

- 日期：2026-10-04
- 状态：已采纳；按两期实施，本轮只采纳设计，不实施登录防护或 TOTP。
- 关联：[OPT-30](../../engineering/optimization-plan.md)、[ADR 0002](0002-administrator-session.md)；外部技术依据核验日期：2026-10-04。

## 背景

当前数据库全局失败计数在 15 分钟内失败 5 次后锁定新登录 15 分钟，任意来源均能触发；有效会话读取和退出不检查这个锁。现有配置没有可信代理、来源计数或第二因素，管理员创建和密码重置只通过本机交互 CLI。

用户已选择仅通过 Tailscale/WireGuard 私网访问，不开放公网端口；部署前必须落实私网准入、防火墙和来源防护。TOTP 与恢复码作为后续可选增强；任何未来公网开放都须另行授权，并且必须先完成第二期及其验收。

## 决定

**第一期：部署前必须完成的私网与来源防护。** 当前 T05-3/T05-4 工作不包含这一实施范围。

- 网页/API 与后端只绑定私网或本机，不开放公网端口；主机、防火墙及容器端口映射共同拒绝公网直连，私网仍保留 HTTPS、Argon2id、生产 Secure Cookie、Origin 与 CSRF。Tailscale 明确允许的用户/设备和目标端口；WireGuard 明确 peer 与允许访问的网段/端口，不能把加入私网等同于获准访问全部服务。[Tailscale 官方访问控制](https://tailscale.com/docs/features/access-control/acls)。
- 新配置 `COINPUP_TRUSTED_PROXIES` 仅接受明确 IP/CIDR，默认空、禁止 `*`；未受信任的连接忽略全部 `X-Forwarded-For`。从真实连接对端建立信任，从右向左剥离可信代理得到第一个不可信来源，规范化 IPv4/IPv6；可信链格式错误、超长或缺失时采用不可由头部选择的对端来源桶。
- 只保留一个代理解析边界：应用保存原始连接对端并负责解析，部署使用 `--no-proxy-headers`，避免被 Uvicorn 改写的 `request.client` 再用于判断代理可信；反向代理覆盖外来转发头，后端只允许代理直连。不存在反向代理时保持可信代理列表为空。[Uvicorn 官方配置](https://raw.githubusercontent.com/Kludex/uvicorn/master/docs/settings.md)、[Nginx 官方 realip](https://nginx.org/en/docs/http/ngx_http_realip_module.html)。
- 按规范化来源 IP 保存数据库失败计数、窗口和冷却，不能按客户端提供的用户名拆桶。跨 worker、重启及并发更新不能绕过；过期来源记录有保留上限与清理机制，异常高基数由入口速率限制兜底。第二期加入的 TOTP/恢复码失败继续计入同一来源。
- 保留原候选默认阈值：每来源 15 分钟 5 次失败、冷却 15 分钟；全局兜底为 15 分钟 100 次失败、冷却最多 30 秒。这些是本项目参数而非外部标准；拒绝中的请求不延长冷却，到期可恢复，成功仅清该来源计数、不清其他来源的失败。保留通用 `401 invalid_credentials`、`429 login_rate_limited` 与 `Retry-After`。
- 来源限制不能消除同 NAT 误伤或多来源攻击，全局兜底仍可能短暂阻止新登录，因此同时保留私网准入和入口总请求预算。失败、限流不撤销有效会话，也不阻止会话读取、退出或合法账务操作；只有管理重置才有意撤销会话。[OWASP 登录锁定与拒绝服务提醒](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#account-lockout)。

**第二期：TOTP 与恢复码。** 私网阶段可选启用，当前不实施；在开放公网之前必须完成、启用并通过恢复与重放防护验收，不能仅以存在配置选项视为满足前提。

- TOTP 默认未绑定，仅通过服务器交互 CLI 绑定、替换或重置；新密钥与二维码仅在本地绑定时展示，输入有效验证码后事务性启用。不提供公开绑定/重置入口，密码重置不隐式关闭第二因素。
- 六位码、30 秒步长，仅接受服务器当前步或上一时间步；数据库原子记录已接受时间步，使用过的码不得再次接受，两次并发只能成功一次。密钥加密存储，独立受限服务器密钥不放入数据库或普通 bundle；恢复和轮换须保留可解密旧密钥的受控路径。[RFC 6238 第 5–6 节](https://www.rfc-editor.org/rfc/rfc6238.html#section-5)。
- CLI 生成高熵恢复码，只显示一次、只存散列；与密码共同验证，成功消费原子化，并发只能用一次。更换恢复码使旧码失效；耗尽或遗失经本机 CLI 重置。绑定、替换、重置追加无秘密的安全审计并撤销旧会话；禁止验证码、密钥、二维码、恢复码出现在命令参数、错误或日志中。[NIST SP 800-63B-4 恢复码存储与限流依据](https://pages.nist.gov/800-63-4/sp800-63b.html#saved-recovery-codes)。
- 登录请求增加互斥的可选 `otp` 或 `recovery_code`，不接受查询参数；已启用 MFA 时必须提供其一。用户名、密码与第二因素全部成功后才建立会话、撤销被替换的旧会话。未完成 MFA 或失败替换不得撤销原有效会话；响应保持原会话模型，不暴露“密码已通过”等中间结果。

## 影响

- 第一期只引入来源计数迁移、可信代理与来源/全局阈值配置及网络部署约定；处理旧全局锁状态，避免沿用旧参数导致全局误锁。私网阶段的原密码登录继续有效，不提前增加第二因素字段或依赖。
- 第二期另行引入 MFA 密钥/已接受步、恢复码消费与安全审计迁移，以及登录/网页输入、交互 CLI 和受限密钥来源；更新 OpenAPI、生成类型和配置示例。两期分别更新运维，说明网络边界、代理参数、首次绑定、恢复码保管、重置和密钥恢复。
- 使用真实部署验证 Argon2 成本和总请求预算；数据库不可用继续通用 503，不回退到进程内计数或放行。保留单管理员、Cookie、过期/撤销、Origin/CSRF 与响应脱敏；不得因采纳本 ADR 宣称服务器已部署或已受保护。
- 第一期验收：未获准私网设备及公网均不能访问服务；直连伪造头、可信/不可信多跳、IPv4/IPv6、错误或超长链不能绕过；并发计数、跨进程/重启、同来源冷却与另一来源正常登录、全局兜底上限及到期恢复均有效。
- 第二期验收：RFC 时间向量、窗口边界、暴力尝试、TOTP 重放与恢复码并发一次消费、旧码失效、CLI 未确认绑定不启用、密码与 MFA 独立重置、密钥恢复及未启用时兼容旧登录；已启用而因子缺失/错误时不发会话。
- 两期均验证失败与攻击计数不误锁有效会话、失败替换不撤销旧 Cookie，代理/API/CLI 日志无秘密。未来开放公网须另行评审部署暴露面；第二期完成是必要条件，不是开放授权。

## 备选方案

- 只调高全局阈值，或只接入私网：均未采用；前者仍允许来源攻击影响所有者，后者仍有被允许设备及代理配置风险，第一期同时采用私网准入和来源防护。
- 立即强制 TOTP：未采用，私网阶段保留选择；但在任何未来公网开放前，第二期的 TOTP/恢复码及恢复验收必须完成。
- 公网直连、邮件重置、WebAuthn/passkey：本决定不实施这些范围，不增设公开恢复接口，也不替换当前 CLI 信任边界。
