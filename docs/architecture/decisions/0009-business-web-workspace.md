# ADR 0009：真实账本工作区与网页状态

- 日期：2026-10-03
- 状态：采用；实际验证见 [当前状态](../../engineering/status.md)
- 任务：T04，接续 [结构接口](0004-owned-ledger-structure.md) 和 [当前业务状态](0008-operation-revisions-and-cancellation.md)

## 页面与交付顺序

保留 React/TypeScript/Vite、既有登录和中英切换。登录后进入实际账本工作区，默认显示所选主体的账户原币余额。导航提供总览、账户、分类、账本资料和设置；服务连接检查放到设置。没有主体时显示创建入口，不放置虚构余额或收入图表。

T04-1 先交付主体/地区资料、账户、分类和余额查询。T04-2 再接入期初、收入、支出、转账、换汇、手续费和记录查询，后续接入更正、撤销、历史和资产配置。每个增量均需要真实浏览器与后端验证，不能把管理页面完成等同于完整手动记账闭环。

公司表单根据国家和类型显示资料：大陆统一社会信用代码、香港 BRN/历史 CR/替代 UBI、美国 EIN 与州编号、爱沙尼亚 registry code/VAT。地区与类型沿用后端枚举，资料编号均为可选字符串。官方字段来源和核验日期随 `regions.ts` 版本保存；这些来源用于字段说明，不构成年审或税务截止日推算规则。

法定名称、登记日期、联系方式和自定义资料可稍后补齐。银行及钱包信息属于具体账户，支持同一公司多个账户。编辑保留自定义和旧地区资料，避免切换界面语言或地区时隐式删除数据。附件与提醒使用后续独立结构，本增量不提供不可用的上传入口。

## 当前主体与访问状态

URL 查询参数保存当前视图和主体 ID，刷新后重新从服务端验证会话并读取数据。数据只放组件内存；不持久化 Cookie、CSRF 或私人业务列表。主体切换中清楚区分旧账本和新账本，旧请求取消或结果丢弃；账户、分类和余额按账本 ID 共同展示，不将上一账本结果套到新标题下。

API 客户端只向同源 `/api/v1/` 请求，携带 HttpOnly 会话 Cookie；写入时显式传入当前内存中的 CSRF，财务命令额外传入幂等键。错误保留 HTTP 状态、业务错误代码和字段位置，不保留服务端回显的私人输入。任何业务接口 401 都清除工作区并返回登录入口。

列表按后端边界分批读取，不能因为每页 100 条就把未读取记录当作不存在。刷新或加载期间禁用依赖旧版本的行操作，保存失败保留当前表单输入。资产停用或账户归档不隐藏已有余额；使用状态标志标注停用项目。

## 表单与并发

表单打开时捕获 `expected_version`，后台刷新不能静默更新该版本后覆盖别人的更改。409 时保留用户输入并解释冲突，只有明确选择“重新载入”才替换为服务端最新值。语言切换仅改变标签，不能重建表单或改变编号、日期和金额。

结构新增表单生成稳定客户端 UUID，在同一表单重试中复用，降低响应丢失后重复建记录的风险。连接中断时说明结果可能未确认，刷新核对已有列表。结构接口的唯一 ID 冲突不会被客户端假装成功；财务表单将使用更严格的完整请求与幂等键保留协议。

分类类型与父分类在编辑时保持固定，名称和中英标签可以修改。归档保留历史引用；归档主体暂停新操作，恢复入口始终可达。正在填写表单时固定操作所属账本，防止切换主体后把草稿提交到别处。

## 精确显示与手机布局

资产金额、编号、日历日期保持字符串。金额工具使用 BigInt 最小单位计算、按字符串分组显示，禁止 `Number`/`parseFloat` 作为金额中间值。账户余额按资产分别展示，未接入汇率前不输出不同币种相加的总额。

保留浅色背景与绿色导航；桌面使用侧栏，手机改为可见的账本选择与导航。表单在窄屏单列，长资产身份和 38 位数量可换行，不让整页横向溢出。表单提供关联标签、键盘焦点、保存状态和错误提示。

## 验证

真实 Playwright 在桌面与手机尺寸运行：登录/刷新/退出，四地区字段切换，中英草稿保留，创建公司和个人、独立分类模板、父子分类编辑及归档恢复、多资产精确余额、主体切换、两标签页真实版本冲突和明确重新载入。接口与金额工具另有无需数据库的 Node 测试。

本地布局检查可拦截接口提供明确虚构数据，只用于截图和视觉审查，不代表真实记账或持久化验收。真实服务测试必须在 CI 的一次性 PostgreSQL 与管理员环境执行，不使用真实账户或账单。截图、执行版本与实际结果记入状态文档。
