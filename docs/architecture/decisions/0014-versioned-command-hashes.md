# ADR 0014：财务命令摘要版本与原请求重放

## 背景

永久回执保存请求摘要。换汇、修订及其嵌套模型的默认字段若随模型扩展而进入摘要，会使旧请求重试得到错误的内容冲突。旧回执不可改写，金额文本、数组顺序和所有财务语义必须保留。本决定接续 ADR 0005、0007 和 0008 的幂等规则。

## 决定

- 回执增加 `hash_version smallint NOT NULL DEFAULT 1`，只允许 1 和 2；升级保留全部旧字段，将原回执识别为 v1。新成功回执显式保存 v2，摘要和原响应在同一财务事务提交。
- v1 冻结当前七类命令的完整投影与默认值，包括费用、分类拆分、修订替代内容；以后模型增加默认字段不能进入 v1。四类原命令省略费用与空费用仍等价，换汇和修订保留其原有默认表示。
- v2 使用收到的原始 JSON 对象，键排序、紧凑分隔、Unicode 保留且拒绝非有限数；与动作、固定路由模板和账本 ID 一起求 SHA-256。更正、取消另外包含路径中的业务 ID。
- HTTP 依赖读取缓存请求体，业务校验与入账仍使用 Pydantic 模型。v2 不补默认值：省略字段、显式 null、空数组以及不同金额拼写可产生不同摘要。对象键顺序和 JSON 空白不影响摘要，数组顺序保留。
- 服务调用可以显式传入原始 JSON；没有 HTTP 请求体的内部调用使用模型中明确设置的字段投影。此内部调用边界不能被当作 HTTP 原文，也不得替代网页冻结的原请求。
- 先读取回执版本，再按对应算法校验；回执匹配后在任何归档、有效引用和当前业务版本校验前返回原响应。未知摘要版本按回执完整性错误处理。
- 存在 v2 回执时拒绝降级到没有版本字段的结构，防止把 v2 误当成 v1。只有空库或全部 v1 回执才可移除版本字段；不修改或删除历史规避降级保护。

## 影响

既有 v1 回执的摘要、JSON、HTTP 状态和重放结果不变；新请求的正文等价规则由 API 约定说明。七类接口的财务执行与响应形状保持原状，网页继续冻结原正文和幂等键。备份恢复保留摘要版本。真实旧结构升级测试须覆盖五类创建、更正和取消，含当前状态已超过旧回执版本的场景；未来默认字段测试覆盖嵌套费用、拆分和替代模型。

## 备选方案

继续对模型完整导出求摘要会随默认字段漂移；全部改用 v1 字段白名单会忽略未来新意图。改写旧摘要需要猜测原请求并破坏永久回执，因此不采用。原始字节摘要会把无意义的空白和对象键顺序当作不同意图，规范化 JSON 更适合现有客户端。
