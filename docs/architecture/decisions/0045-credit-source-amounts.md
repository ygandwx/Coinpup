# ADR 0045：贷项原行净额、税额与分类金额计划

- 状态：已采纳（已确认业务规则的金额技术细化）
- 日期：2026-10-15
- 依据：用户确认部分贷项手填净额/税额、冲减原分类；P-03、B-11、ADR0026/0039/0044。

## 背景

退款只改变实际资金，不能承担贷项的经营分类冲减。原单据按方案A逐行计价并封存净额、税额和含税额；部分贷项不能重新套用税率，也不能把含税数量反推为未经用户确认的净额和税额。

## 决定

- 本ADR只规定原行金额与方向的纯计划。输入源是已封存单据行的同账本身份、单据类型、原分类/项目、完整资产定义及原净额/税额/合计，以及该行已累计贷记的净额和税额；用户输入本次净额和税额的原币十进制字符串。
- 原净额和税额均非负，合计为正且精确等于两者之和；累计已贷净额、税额各自非负且不能超过相应原值。异常历史直接拒绝，不夹取为零，不改写来源。
- 本次两项均非负、合计必须大于零；每项分别不超过该项剩余额度。允许净额或税额其中一项为零，不据手工拆分重新推断税率或税务资格。零总额源行不可生成贷项。
- 所有数量使用Amount和完整AssetDefinition，经整数最小单位精确计算；超资产精度即拒绝，不四舍五入。不得混用不同资产、网络或精度，不通过浮点或Decimal默认上下文计算。
- 保留原单据/源行、分类与项目身份。客户Invoice贷项：income增加含税贷项额，receivable.customer减少同额；供应商账单贷项：expense减少含税贷项额，payable.supplier增加同额。两侧同资产配平，不写资金账户行，不改原分类/项目，不另加税额分录。
- 返回本次净额、税额、含税额、两侧方向和剩余净额/税额；不代替持久事务或永久回执，不把纯计划结果当作已保存业务事实。

## 影响

本金额计划没有API、迁移或写入。后续完整贷项技术协议须确定原子持久边界、日期及期间校验、原单据版本与净未结容量、明确分摊退回、v2回执和恢复；不能直接把此纯函数暴露为入账入口。任何事务仍须保留账本隔离、不可变历史、原意图重放及咨询锁顺序。

验证使用明确虚构来源，覆盖两种单据方向、净/税单独限额、累计部分贷项、零侧数量、最小单位/最大数量、低Decimal精度、跨账本/资产/网络拒绝，以及本金不触及实际现金的计划形状。

## 备选方案

按原税率自动拆分会覆盖用户确认的手填决定；只限制含税总额会容许税额或净额单独超贷；把退款自动转成负费用会重复确认经营变化。分别限制净额/税额并保留原分类能清楚区分这些事实。
