# ADR 0007：实际换汇数量与独立手续费

- 日期：2026-10-03
- 状态：采用；执行证据见 [当前状态](../../engineering/status.md)
- 任务：T02-5 / T03，接续 [ADR 0005](0005-atomic-posting-and-receipts.md) 和 [ADR 0006](0006-same-asset-transfers.md)

## 实际成交事实

换汇记录实际转出与转入的两种资产及各自数量，不用市场行情替换成交量，也不把本金记成费用。比如转出 100 USD、收到 90 EUR，另付 2 USD 手续费，余额变化是 USD -102、EUR +90，费用只有 2 USD。

两个账户都属于当前账本；同一个多资产账户可执行 USD→EUR 换汇。转出和转入的完整资产 ID 必须不同，包括不同网络/合约的代币身份。相同资产账户间移动使用转账；跨主体结算仍属于后续任务。

手续费可从本金账户或同账本其他账户扣取，也可使用第三种资产。明确选择扣款账户、资产、正数金额和费用分类，原始费用单位不会被隐式换算。收入、支出和转账支持可选手续费，期初不允许附加费用。

## 命令与响应

`POST /api/v1/ledgers/{ledger_id}/exchanges` 复用会话、Origin/CSRF 及必填 `Idempotency-Key`，请求包含：

- 可选稳定客户端 `id`、交易日 `transaction_date`、可选 `description`。
- `source_account_id`、`source_asset_id`、十进制字符串 `source_amount`。
- `destination_account_id`、`destination_asset_id`、十进制字符串 `destination_amount`。
- 可选 `fees`，最多 20 项，每项是 `account_id`、`asset_id`、`amount`、`category_id`。

两项实际本金数量均须为正且符合各自资产精度。换汇归属日采用交易日；手工收支仍保留显式业务归属日。手续费随命令保留日期，不另造一项脱离本金的日期默认值。

新 `ExchangeResponse` 以 `kind="exchange"` 加入流水判别联合类型，返回两端账户、资产、实际数量及费用。已有收支/转账响应只在确有手续费时增加 `fees`；空费用不改变旧响应 JSON 结构。GET、POST、列表和回执重放使用同一表示。

## 本金与费用分录

在 `JournalLine` 增加不可变 `component_no`：0 为本金，1–20 为按请求顺序编号的手续费。旧分录升级后全为 0，不改变旧金额或财务含义。

| 部分 | 分录构成 | 不变量 |
| --- | --- | --- |
| 换汇本金 | 转出账户 -S、兑换对方行 +S；转入账户 +D、兑换对方行 -D | 四行、两种资产；各资产独立平衡，兑换行无费用分类 |
| 每项手续费 | 指定账户 -F、指定费用分类 +F | 两行、同一资产、等额反向；单独编号且费用为正 |
| 原有命令本金 | 期初、收入、支出或转账原有规则 | 在 component 0 上继续校验，不能用手续费掩盖本金不平衡 |

数据库同时校验每个组成部分与整张分录按资产配平，禁止手续费混入期初、分类或角色引用不符、费用编号不连续或组成行数错误。不同编号可以记录金额和分类相同的实际费用。所有行继续受资产精度、账本复合外键、不可变和封存保护。

服务按顺序锁定所有涉及资产，在任何写入前验证本金和全部费用。按 `(account_id, asset_id)` 合并本次所有增减，再验证最终余额范围；不能只检查本金、漏掉叠加手续费，也不能因为合理抵销前的中间值而误报溢出。所有本金、手续费与回执在同一事务提交。

读取时按组成部分还原本金和费用，原有“唯一账户行”规则只用于对应本金部分。账户余额仍求和全部账户行，收入/费用分类统计包含正确分类行，兑换对方行不属于收入或费用。

## 旧请求的幂等兼容

给请求模型增加默认字段会改变一般的 `model_dump()`，进而破坏已保存摘要。因此明确冻结期初、收入、支出、转账四类旧命令的字段集合和默认值，包括 `id:null`、空描述、原金额文本及分类顺序。空或未提供的费用使用完全相同的旧摘要；非空费用显式进入扩展摘要。不能改用 `exclude_unset` 或重新规范化金额拼写。

固定的旧摘要样例在修改前从上一增量实现计算；回归测试验证新代码的四类无费用摘要一致，也验证旧持久回执在升级后仍重放。已有回执不补写新字段、不改写历史 JSON。金额字符串拼写差异仍按原合同视为不同请求。

## 迁移与验收

迁移 `20261003_0006` 增加组成部分字段、兑换角色与类型并扩展校验函数。降级前锁定财务表；若存在换汇或手续费历史，明确拒绝，而不是删除/降格解释记录。无新型记录时可恢复冻结的旧校验规则。

验收包括 A-05 的 USD 898/EUR 90、A-07 的 BTC `0.89999000`、同账户换汇、第三账户/资产扣费、到账资产扣费、精度、并发、最后一项费用非法时整笔回滚、最终合计余额范围，以及旧摘要和回执 JSON 兼容。恢复演练增加实际换汇和 BTC 本金/费用组合，重放原请求后全部表不变。

展示行情、税务计算、投资盈亏和真实链上转账均不由这组命令执行；它们只记录用户确认的已发生数量。完整验证结果及尚未完成的界面工作以状态文档为准。
