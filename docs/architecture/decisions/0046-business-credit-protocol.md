# ADR 0046：独立贷项的整组事务与原意图回执

- 状态：已采纳（既定贷项口径的技术细化）
- 日期：2026-10-21
- 依据：P-03、B-11、ADR0014/0015/0039/0041/0045。

## 背景

贷项纯金额计划尚不能保存业务事实。贷项需减少原分类及往来，并与既有分摊共享净容量，不能修改封存单据、重复记现金或令旧回执随余额变化。

## 决定

- 新增独立business_credit命令：稳定UUID、原单据ID及expected_version、明确credit_date、原因、有序原行列表。每行只接收source_line_id、手填net_amount/tax_amount和明确recognition_date；不允许更换原资产、分类、项目或往来。1–200行，同一原行不能重复。
- 沿用既有单据的交易日/逐行归属日分离：credit_date作为新事实交易日，不早于原开票日；recognition_date由用户明确填写，不从旧归属日或当前时间静默推断。所有新交易日及归属日均须开放；原单据期间关闭不要求重开，新贷项不冒充原日期的错误更正。
- 按ADR0045分别限制原净额和税额累计贷记；合计为正。原行可继续结算量＝原含税额－累计贷项含税额－净已分摊额，必须非负。需要释放已结款项时先明确保存分摊退回，不在贷项请求中猜测来源、隐式退款或自动串接两次写入。
- 原单据总额和applied_amount含义不变；当前outstanding_amount扣除贷项。无贷项时现有结算JSON逐值不变，不给旧回执补字段。新增贷项容量读取分别展示原净/税、累计贷净/税、净分摊和可贷额度；余额只用于新意图，不能证明旧提交成功。
- 整组一个事务，每个请求行一个独立invoice_credit或bill_credit操作及两条同资产分录。保留原party/document/document_line/project维度，分类方向与原应计相反，控制账户使用receivable.customer或payable.supplier。净额/税额仅作明细，不另记税费、现金或exchange行。
- 新命令使用咨询锁→账本→主体→排序资产，READ COMMITTED锁后重读封存来源及净容量；新贷项和新分摊共用锁和容量公式。原资料归档不改封存维度，主体和实际使用资产/控制账户必须可用。任一步失败，整组分录、贷项、系统账户、回执与changes全部回滚。
- 不可变头表及行表保存原单据/版本、顺序、净/税/合计、日期、原因和源应计操作→新操作/凭证映射。同账本复合外键、封存/不可变、逐行形状及累计容量延迟约束全部成立后才开放写入；新表接入changes，有历史拒绝降级。
- `POST /api/v1/ledgers/{ledger_id}/business-credits`绑定独立v2动作与原JSON。沿用永久账本键；201回执含贷项/原单据/源版本、资产、日期及完整有序行映射、原净/税/含税数量。锚点取请求第一行新操作，只作既有非空FK，不代替整组。
- 原键重放先于当前版本、容量、归档、停用和期间检查；核对保存的不可变完整组与原回执，不按当前有效量重建回执。旧v1/v2摘要、确认/付款/退回/退款回执逐字保留，未知结果只重试原键和原正文。
- 列表/详情/容量使用现有鉴权、只读快照、no-store及有界分页。网页冻结所有者、账本、原行/资产及完整审阅内容；中英切换不重建意图，401同用户显式恢复，重复/迟到响应不重复写入。
- 旧普通更正/取消入口不得操作贷项子凭证；整单修订需另一个整组协议处理依赖，不借此次新增命令改变原操作历史链。退款仍是独立事实，本协议不自动创建或取消真实资金记录。

## 影响

按契约与摘要→存储→数据库完整形状/容量→原子服务→API/恢复→网页拆包；没有完整约束时不提供写入口。结算的贷项扣减须在开放贷项写入前同时覆盖读、服务及数据库，并保留无贷项响应回归。

使用虚构数据验证两种方向、净/税独立限额、明确分摊退回、最小/最大金额、200行、低Decimal上下文、日期/期间、并发容量、整组回滚、跨账本、旧回执、归档后重放。完整bundle在空目标恢复后重放原确认/分摊/退回/退款/贷项，全部表及通知不变；网页验证三宽度中英、重复提交、未知结果、真实401与失败保留。

## 备选方案

直接改原单据或生成负付款会混淆历史及资金；只在服务检查容量不能防止数据库绕过；隐式退回会把独立已保存事实伪装成一笔操作。独立组、明确源行和共享净容量保持现有财务边界。
